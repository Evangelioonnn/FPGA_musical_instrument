## 1. 按可独立交付的子系统分工

| 负责人 | 主责 | 第一份可验收交付 | 最终交付边界 |
|---|---|---|---|
| 用户：实时音频核心与系统集成 | DDS/ADSR、声部、混音、多音色、所选效果器；统一时钟/复位、顶层、CST/SDC、最终资源/时序、板上音质定位 | 已有M1/M2基础上提供有规格的音符入口、参数入口及状态输出；标明已实现与拟扩展字段 | 稳定音频核心、仿真/构建脚本、资源/时序/延迟结果、最终集成工程 |
| 队友B：演奏交互子系统 | 比较交互布局；选音、连续表达、编码器/踏板等硬件；扫描/传感需求、校准、线束、后续PCB和结构 | 用现成模块搭一个选音输入＋一个独立连续控制，给出线序/电压/测量值及按下/松开/噪声记录 | 原理图、BOM、连接器表、测试记录；如有板上固件/数字接口，交付其源码、协议及测试工具 |
| 队友C：通信与可视化子系统 | 蓝牙选型/收发协议、手机端最小交互；FPGA侧状态显示与所选显示驱动/小型外围RTL；支线仿真和构建 | 分别用模拟数据验证状态显示、手机设置一个参数并读回；两部分可独立测试 | 模块/客户端/协议、外围RTL或已约定的驱动规格、独立测试、资源与刷新率记录 |

用户保持合成核心唯一维护入口，队友可以交付边缘驱动模块而不修改合成算法。若用户希望所有FPGA RTL也亲自实现，则B/C必须先给完整电气/时序规格、模拟输入和期望输出，并把用户需要写的每个适配器列入计划；不能将这些工作隐含为最后的“接两根线”。

验证由各模块负责人完成，三人都能复现；不把所有调试和测试集中给用户。B/C的职责不限于焊接或界面截图，必须交付可以接入的子系统。

## 2. 两类资源分别约定

**板外接口预算先行**：确认需要多少行列线、编码器输入、模拟通道、串行总线、显示信号和电源能力，再核对Bank/连接器/实际针位。用户和B/C共同迭代需求，不能先随意分配一组IO后要求所有交互迁就它。音频和板载时钟已确认使用V22/Y17/AB17/AA16/AB16；新增端口本草案不指定引脚。

| 支线 | 初步接口需求示例，非接线承诺 |
|---|---|
| 开关矩阵 | R行＋C列；物理外形与电气矩阵分开，无二极管多键限制需解决 |
| EC11 | A/B/SW通常3根信号，另加电源/地；实际模块电压和上拉须核对 |
| 压力/位置传感 | 按器件选择模拟ADC通道或数字总线；模拟输出不能直接当普通数字GPIO读取 |
| 蓝牙 | 若选UART型模块，通常TX/RX，加模块可能需要的使能/状态/流控；电平及协议以型号为准 |
| 显示 | LED、SPI小屏和HDMI的IO、存储及驱动成本不同，先选择一级目标再分配 |

**FPGA内部预算滚动测量**：DSP/BSRAM/Logic/时序按功能预算与综合结果调整，不等最终声部/效果器完成才让队友开工。现有M2自动演示为2007 Logic、438寄存器、4 BSRAM、4 DSP；该数字不是完整系统最终占用，也不是新增支线的现成资源配额。C每增加波形缓存、显示帧缓冲或FFT都应单独报告代价，给音频核心保留规划余量。

没有新增器件型号和完整官方引脚核对前，只冻结逻辑接口与电气需求；PCB投板前再冻结连接器针位、信号方向、Bank电压、供电和实际CST的一致性。

## 3. 输入板的边界先说明

默认先评估“传感器、开关、分压/ADC及连接器的交互板”，由FPGA执行适合放在其中的扫描、去抖、事件和参数处理。B负责硬件功能及可测输入，用户负责约定内的FPGA接入，必要时B可贡献外围RTL并由用户集成。

若B提出加入单片机作为输入控制器，应明确其采集/滤波/传输职责、协议、最坏时延与断线释放行为，再评估产品和比赛的展示目标，不能无意中更改架构。官方要求完整音频生成通路由FPGA HDL实现；不能据此推导一切外围单片机都被禁止，也不能把输入板变成外部音频合成器。

外形仍按用户最新意图：网格、琴键及其他交互平等考虑，4×4仅验证。先用现成模块或小样确定手感与信号，再做集成PCB，不要求B第一次提交就是整块成品板。

## 4. 三方共享的接口契约

同日夜间批次后新增可用候选：`project/expression/INTERFACES.md` 已给出真实实现的音符kind/on/off/retune、力度、配置写入应答、音量/音色/弯音/滑音/踏板/ADSR及声部/峰值反馈。以下M2条目保留基础接口背景；新接入优先评估expression候选，不能把其数字验证当成真实传感器、UART/BLE协议或显示驱动已完成。实际板卡接口仍须双方核对。

| 边界 | 约定内容 | 当前状态 |
|---|---|---|
| 输入→核心：音符事件 | 按下/松开、音符号、握手；物理键与音符映射、同音叠按、持键换八度规则 | M2已有同步50MHz的event_valid/ready、event_on、7位event_note；无力度字段、无输入FIFO |
| 控制→核心：参数 | 参数含义、范围/单位、作用声部、有效时刻、平滑策略、本地/蓝牙冲突时的优先级 | 拟设计，不把蓝牙收到的任意字节直接写入合成寄存器 |
| 核心→反馈：状态 | 当前音符/声部、held/occupied区别、音色、峰值/削波、所需波形与刷新周期 | M2已有部分声部诊断和样本输出，显示/通信适配尚未实现 |
| FPGA↔模块：物理协议 | 电压、方向、连接器、总线格式、校验/版本、应答、容量和丢包策略 | 依具体外设冻结；UART只是传输方式，不是完整协议 |

内部音频维持sys_clk单时钟与sample_ce；外围异步输入按接口同步。慢速显示/蓝牙不应反压或暂停音频采样，状态可降采样、合并为最新值；控制命令和按键事件的处理/溢出规则另定，不能随意丢弃松键导致挂音。后续声部数变化应参数化状态宽度或通过协议描述数量，避免C将显示写死为四路。

## 5. 蓝牙和可视化的实际范围

蓝牙第一阶段只做参数设置与状态回传，例如修改一个参数、收到应答、读回实际值。先核对模块是BLE还是经典蓝牙、对应手机系统、串口电平和固件协议；所谓BLE串口透传仍需要匹配的服务/特征与客户端支持。现阶段不假定具体模块可即插即用。

本地演奏和音频输出保持独立运行，不让蓝牙连接周期/手机状态决定控制到声音的基础时延。蓝牙断开后本地乐器继续可用。实时音频传输、录音回传和完整App分别计工作量，普通蓝牙串口模块不等于蓝牙音频模块。

可视化分层：①音符/活动声部/音色/削波状态；②有明确显示需求后增加波形；③FFT频谱作为资源和时序允许时的进一步扩展。选其中一级作首轮目标，避免同时开发所有显示。

官方选题二拓展要求包括“基于FPGA硬件逻辑实时生成可视化反馈”。据此，若该支线用于对应这一指标，应交付FPGA内生成的LED/显示反馈逻辑及其证据；手机端画图是附加呈现，不能自动等同于已经完成该项FPGA实现。若做FFT，应单独验证谱峰、幅值和吞吐量，不能用动画冒充实时频谱。

## 6. 只有一块FPGA时怎样推进

- 用户持有主板，负责当前音质问题、最终约束及集成；B/C有需要时预约短时间板测，每次明确待验证项和工程版本。
- B先完成布局小样、通断/电压/传感器测量；若已有MCU或采集工具，可临时读取传感器验证，不因此决定最终架构。FPGA扫描适配先用行为模型仿真，真实整条输入延迟仍需上板。
- C用PC测试工具生成核心状态/参数应答，独立验证模块通信和手机端；FPGA显示/串口外围RTL用独立testbench、综合及资源报告验证。测试数据通了不等于真实FPGA链路已通过。
- 第一轮只集成“一个输入能控制音符”“一个状态能点亮反馈”“一条参数命令能设置并读回”，尽早暴露接口问题，然后逐项扩展。
- 不等最终PCB/完整App才首次集成。PCB应留出小样、打样、焊接和改版时间，制造计划跟随实测与供应周期确认。

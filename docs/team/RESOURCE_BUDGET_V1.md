## 2. B：外接IO、交互与电气预算

### 2.1 可用信号池

B的主要约束确实是**可接出的IO、电气、扫描延迟和供电**，也包括面板大小、走线与手感。芯片报告的297个IO不是297根可随便插杜邦线的接口。

除两组PMOD的16根信号，J13 40针还提供36根直接信号、2根经电阻选择的信号及5V/GND。以**J13直接信号+PMOD共52根独立信号**作为候选池；确认J13第29/30针的电阻后可增加2根。另一个J14/SDRAM1排针在该图中标为不装且与PMOD等共享，不能重复计数。

| 使用方 | 常规目标 | 预留上限 | 用途 |
|---|---:|---:|---|
| B控制板，优先J13 | 16–24根 | 先预留32根直接信号 | 键区、旋钮、连续表达采样、踏板及LED驱动连接；超过时可在总池内重新分配 |
| C蓝牙，优先PMOD | 2根 | 4根 | UART TX/RX；额外两根供RTS/CTS或模块控制选择，不能两种都重复占用 |
| J13直接信号余量 | — | 4根 | 36根减去B预留32根；另有2根条件信号待确认 |
| PMOD余量 | — | 12根 | 16根减去C预留4根；仍使用的旧验证外设须先扣除 |
| **直接信号总账** | — | **52根** | B32+C4+J13余4+PMOD余12；不含2根条件信号 |

当前验证接法为J8矩阵8根、J9编码器2根，共10根，PMOD尚余6根。这是当前验证占用；上表是B后续迁到J13后的分配目标，不能一边把旧10根继续接着，一边把12根PMOD余量全数再分配。B可采用直接行列扫描，不必为12根限制强行增加移位寄存器。

| 连接器 | IO0到IO7的FPGA球号 | 当前用途 |
|---|---|---|
| PMOD0 / J9 | T18、R18、R17、P16、U21、T21、R19、P19 | EC11 A=T18、B=R17已板测 |
| PMOD1 / J8 | Y21、Y22、AB21、AB22、AA20、AA21、AA19、AB20 | 4×4矩阵已用于双音色演奏 |
| J13 / SDRAM0，40针 | [完整针号/球号表](../board/J13_GPIO.md) | 36根直接GPIO+2根条件GPIO，资料核对完成，待实物接线验证 |

这是球号清单，不是连接器物理针序。物理针号/观察面以[IO表](../board/IO_RESOURCES.md)、已验收的[矩阵接线](../../project/input/matrix_playable/WIRING.md)及实物核对为准。B先交功能针表，A/B/C再分配确切球号；预算不要求现在移动已接好的线。Y22在当前矩阵占用里，不能另按冲突的显示原理图候选再占用。

### 2.2 可选的12根串行扩展示例

J13允许B直接使用更多行列/控制线。下面保留的12根方案仅供线束紧凑时比较，不再作为B必须遵守的总上限：采用行输出移位寄存器、列输入移位寄存器、SPI ADC和带输出锁存的LED移位驱动。

| 信号 | 数量 | 说明 |
|---|---:|---|
| 共享串行SCLK、MOSI | 2 | 行/灯移位、ADC按时隙使用；模式、电平、速率须兼容 |
| 行输出锁存 | 1 | 输出行状态不随每个串行位乱跳 |
| 列输入并行装载、独立串行返回 | 2 | 输入移位寄存器返回不与ADC返回硬并联 |
| ADC片选、ADC独立返回 | 2 | 选多通道ADC，多个模拟轴不各占一根FPGA模拟脚 |
| LED输出锁存 | 1 | LED移位过程不改变已显示状态 |
| EC11 A/B | 2 | 两相直接采样 |
| 明确存在的旋钮按压/独立功能键 | 1 | 当前模块按压尚未确认，不使用悬空C脚冒充 |
| 备用/直接紧急键/输出使能 | 1 | 按电路需要三选一，不重复承诺 |
| **合计** | **12** | 普通功能键及踏板开关可并入输入扫描 |

串行输入和ADC返回分开，是为了避免常见输入移位寄存器没有三态输出导致总线争用。行与LED各自锁存，按键扫描优先，灯更新不能拖慢扫描。若器件需要额外OE/中断/复位，用备用脚或重新排预算；此表不等于原理图电气已批准。

LED帧的逻辑内容由C生成；若共享B串行总线，统一总线控制器独占物理引脚，C通过内部请求接口提交灯帧，不能两个RTL模块同时驱动SCLK。该总线/输入驱动资源计入输入适配区，C的曲目逻辑/灯帧缓存计入C，不重复计费。

### 2.3 功能目标与B交付

- 按基础≥2维、拓展≥3维设计：例如“选音/和弦 + 就手的压力或吹气强度 + 弯音触条/脚控连续轴”。具体形态由B提出；压力/吹嘴均非强制采购。一个旋钮切三个菜单不算三个独立同时可控维度。
- 建议先为2–4路连续模拟量预留通道、4–8路作器件选型余量。量化从12bit级评估，FPGA侧统一归一化；精度不能替代有效分辨率、稳定性和手感。全局压力是aftertouch/表达，不能冒充逐键击键力度。
- 普通延音、选择性延音、模式/音色键可以是扫描输入；滑音/弯音可用连续轴。音量/释放长度仍可复用旋钮。优先让演奏中常用动作无需离开主键区。
- 最终矩阵要支持目标和弦：逐键二极管或其他独立感知方案。现有无二极管4×4和保守鬼键策略不是成品上限；硬件改变需同步修改扫描策略。
- PMOD及J13的GPIO按相应3.3V电气设计，禁止5V信号直接入FPGA；J13第11针是5V电源，第12针是GND，第29/30针需查电阻选择。板载三用户键是1.5V域。ADC量程、调理、保护、上拉和输出默认态必须落实到具体器件。
- 灯的电流由驱动与供电承担，不从FPGA管脚直接带整排LED；交付最大同时点亮电流、3.3V/5V负载和电源回路预算。供电接法以板卡允许电流核对后决定，不能只凭接口上有电源针。
- 输入采集/扫描/去抖目标最坏≤2ms，包含ADC内部转换/数字滤波等待；不能用“扫描很快”掩盖芯片自身10ms以上的刷新周期。若该手感必须更慢，先明确对≤5ms扩展目标的影响。

B交付：布局及演奏动作图、候选BOM、原理图/PCB、[IO提案](../../templates/IO_PROPOSAL.csv)、完整供电/电平表、扫描时间账、线束图和实测记录。输入RTL按扫描、ADC、标定、事件适配逐项确定作者；**不是B画板就默认全包RTL，也不是未说明就全部转给A**。

J13标为SDRAM0不限制它只能驱动SDRAM；但如果将来C需要此口接外部SDRAM作大缓存，它与B控制板将互斥，须改分配。当前C的片内缓存/程序绘图预算没有占用J13。

## 3. C：屏幕、频谱、蓝牙和脱机引导预算

C的多页UI、带按压旋钮、四谐波编辑、声音分析及脱机引导效果和子预算替代建议见[设计目标](C_HANDOFF_AND_DISPLAY_PLAN.md)。它不增加本表总额度，也不与下列子项重复相加。

C总额度 **13000 Logic / 10000 Register / 26 BSRAM / 16 DSP / 1 PLL**，含IP、字体、素材、所有FIFO、双缓冲和CDC，不只算主要算法。内部可自主调配，建议起点如下，子项不是已经综合的精确预测。

| 子项 | BSRAM额度 | DSP额度 | 目标 |
|---|---:|---:|---|
| 画面/字模/波形与相图/状态跨域 | 8 | 2 | 键区或网格、参数、音高、波形与明确标记的数据图 |
| 窗函数、FFT、工作区与频谱缓存 | 12 | 12 | 时分复用FFT，评估1024/2048点；含旋转因子ROM和运算缓冲 |
| 蓝牙UART/协议队列 | 2 | 0 | 配置、状态、曲谱传输、校验与错误恢复 |
| 曲谱事件、引导状态、灯帧 | 4 | 0 | 脱机节拍、键位指引、实际按键匹配 |
| C内部运算余量 | 0 | 2 | 可用于定标/坐标换算等 |
| **合计** | **26** | **16** | 空间不足先在C内部交换，再讨论总预算 |

### 3.1 显示可直接复用的事实

[dvi_colorbar_probe](../../project/visual/dvi_colorbar_probe/README.md)已在A实物上稳定输出彩条，显示器报告1920×1080、61Hz。使用普通HDMI线和电脑显示器，验证的是DVI/TMDS视频；不包含HDMI音频或EDID自动协商。

| 信号 | P球号 | N球号 |
|---|---|---|
| TMDS data0 | J14 | H14 |
| TMDS data1 | J15 | H15 |
| TMDS data2 | K17 | J17 |
| TMDS clock | G15 | G16 |

这8个物理IO不从PMOD的16根中扣；不可再当空闲GPIO。系统50MHz时钟V22共享，不按模块重复占引脚。探针使用1 PLL、3个OSER10，实际像素150MHz、FCLK750MHz，2200×1125总时序约60.606Hz。C可先复现；若面向更多普通显示器，后续评估148.5MHz标准1080p60模式，不为240Hz显示器设计240Hz输出。

两点在集成时解决：探针Y12复位与音频Y12音色键功能冲突，整机应采用内部显示复位策略；音频J16与显示K17/J17处于报告同一Bank5，两个工程写了不同电气属性，须核对实际VCCIO与器件差分输出规则后统一。不要仅复制两个CST拼接，也不要为了凑一致未经核对改Bank电压。详见[显示事实](../board/DISPLAY.md)。

### 3.2 按比赛目标安排功能

1. **画面和波形**：程序绘制键/网格/谱线，字模或小图块作ROM素材；波形来自实际输出采样。1080p全帧RGB需约6.22MB，不在26块片内RAM预算内。复杂画面可画，首版不依赖全帧缓存。
2. **频谱**：从全速PCM取样，独立分帧/加窗/FFT/幅度定标，不能拿SYSTEM_V0未滤波的48倍抽样流做全频频谱。512点可先调通但每bin约93.9Hz，低音分辨力有限；1024/2048点或正确低通降采样按用途选择。FFT帧等待不进入发声链路。
3. **李萨如**：当前音频左右完全相同，真实L/R图只能是一条直线。可以先忠实显示，也可预留两路独立观测输入；需要漂亮的立体声轨迹时由A提供真实分路/效果输出。延迟相图可展示但要标名，不伪称L/R立体声。
4. **脱机LED引导**：曲谱用“时间/时长/音符或逻辑键/力度”等事件存储，FPGA自己计时、点灯及比较按键。先内置一首可演奏曲，断开手机仍工作；后续蓝牙下载。BSRAM中下载数据断电不保留，如需掉电保存另评估存储；内置ROM曲可随配置恢复。曲谱容量按事件字节数、双缓冲和实际映射报告，不按歌曲文件名猜大小。
5. **蓝牙**：FPGA做UART/协议/队列，模块承担无线。先完成可靠调参、状态回读、曲谱下载、键位映射，再扩充记录回传；本地演奏不依赖无线在线。未支持的音频参数必须NACK或明确禁用。
6. **录音回传**：保留为进阶目标，不用“事件记录”冒充PCM录音。16bit单声道当前Fs原始流约96.2kB/s；UART 8N1仅承载原始样本就需约0.962Mbaud，协议再加，115200不够；蓝牙空口吞吐也须实测。若只做事件记录，明确其产品含义。PCM长录音或不稳定无线需要额外存储/压缩与新预算，不能默认塞进2块通信FIFO。

IP可优先评估PLL、双口RAM/ROM、真正异步FIFO和FFT。先报告FFT配置/点数/位宽/吞吐/延迟及综合占用，再选择实现；不是用了官方IP就必定更省。可将自己的渲染和协议RTL做参数化模块；包成IP不会自动降低资源。

C交付：独立顶层+mock状态/PCM输入、显示测试图、FFT已知频率/幅值对照、LED曲谱演示、通信异常恢复测试、IP配置与生成依赖、资源/时序报告。C自行决定画面与蓝牙内部协议；跨到音频的字段和最终球号由A适配与统一。

## 4. 为后期整合预留的接口边界

以下音频语义已在 V2 核心与[音频接入包](../../project/audio_integration/README.md)中实现，并经数字仿真和组合资源审计；它们仍不表示真实SPI ADC、C的显示/蓝牙外设或最终控制板已接入。不能把历史[SYSTEM_V0](../interfaces/SYSTEM_V0.md)的位布局当成V2接口；声部数由V2能力表给出，不永久绑死8声部229bit快照。

| 方向 | 约定目标 | 责任 |
|---|---|---|
| B输入适配 → A | 物理key_id、按下/松开、可用力度、连续轴原始值/标定值及输入时间 | 输入RTL作者逐项约定；A把事件映射到音符实例，松开原实例，避免换布局后卡音 |
| A → C 状态 | 每声部实例ID/音高/音色、held/gated/occupied、音量/ADSR/释放档、普通与选择性延音、clip/故障、序号/能力表 | A实现真实采样与适配；C不从声部是否占用猜是否仍按键 |
| A → C 音频 | 50MHz域、Fs=50MHz/1040，最终音量/效果/限幅之后且进入DAC串行器之前的16bit有符号L/R PCM；每帧一拍valid和32bit样本序号 | A定义精确取样节点并提供样本；当前L=R照实上报；原始混音如需另作诊断流另命名 |
| C → A 配置 | 版本、事务编号、参数/值、valid/ready、接受/拒绝及实际读回 | A负责统一参数状态与本地/主机仲裁；C负责无线协议和重试。不能主机调完音量后旋钮跳回旧值 |
| C → B灯驱动/总线适配 | 逻辑key_id到LED的映射、灯帧、节拍/提示含义 | C做引导与渲染，B做灯/电源/连线，物理总线只设一个主人 |

基准域50MHz，同步复位；输入外设用时钟使能，首版不因UART/矩阵各造一个时钟域。C复用视频所需PLL产生像素与串行时钟。多位状态用握手快照、音频跨域用异步FIFO或等效正确方案，显示在帧边界接纳状态；不能逐位两级同步凑成总线。

音频输出没有来自C的反压。显示可保留最新帧、统计丢旧快照；FFT若样本溢出/序号缺口，丢弃不完整分析帧、计数并重新对齐，不能将断裂数据当连续波形。蓝牙拥塞只能影响蓝牙，不能延迟note_off或音频采样。C的缓冲及CDC已经包含在26块预算内。

延迟设计目标：B采集/去抖≤2ms，A事件/调度/数字音频≤1ms，另保留≤2ms供接口、模拟输出及测量余量，争取全链路≤5ms，至少满足基础≤10ms。**这是分配目标，尚未实测**；不得把慢起音ADSR的听感等待混同于传输延迟，应定义触发点与输出阈值，测最坏相位和分布。显示刷新/FFT/BLE更新不串在这条路径中。

## 5. 合作节奏与验收

可以独立开发，避免等到最后一天才第一次拼接：

1. B交付包含J13的控制方案，第一版按最多32根直接信号预留，确有更多需求可在总池内调整；C在1 PLL/26 BSRAM/16 DSP内独立开发。各自在任务分支开发，不要求共用Designer工程，也不修改A现有可听音频基准。
2. C先基于mock完成画面和通信测试，再用接入包接口接真实状态/PCM/命令。A与C做一次“已验收音频+已点亮显示+少量真实状态”的最小整机PnR；优先复查Y12/Bank5、跨域与低于0.076ns的时序余量，不必等完整UI或控制PCB。
3. 分批合入波形、FFT、蓝牙、LED曲谱；每次更新资源总账和时序，检查满负载音频截止、重复松键、断连/溢出恢复。
4. 记录各自commit、工具/IP版本、构建命令、有效CST/SDC、PnR与STA；板测另记设备/接线/固件SHA256和现象。提交源码、IP配置、必要ROM数据、测试和证据，`impl/`与`.fs`不进Git。

基础和扩展覆盖由A/B/C共同完成：B保障≥2/3维和低延迟输入，A保障合成/复音/ADSR/实时变调/音色/实际数字效果器，C保障真实可视化、脱机LED指导与蓝牙扩展。第三音色、选择性延音、滑音有产品价值，但延音开关不能代替赛题数字效果器；彩条也不能代替波形/频谱验收。

交接时提供本分支/提交的GitHub链接或仓库相对路径即可。队友不需要A电脑的绝对路径，也不需要从聊天记录猜当前预算。

# 给 C：接入交接与屏幕/蓝牙设计目标

2026-09-29；A整理，供C独立选型和设计。**本轮交付是效果规划及文档整理，没有新增UI、FFT、蓝牙RTL或板测结果。** 界面布局、算法/IP和内部实现由C决定；下面区分已有能力、建议目标和待补接口。

## 五分钟交接

- 当前统一交接基线：`main`；音频/传输代码基线为 `e500e30`，本文件与后续文档维护随汇总PR一起合入。先Fetch并查看最新main的README；从origin/main新建自己的 `codex/c-...` 分支。已从旧交接分支开发的成员提交当前工作后合并origin/main即可，不共同修改A的分支，也不要覆盖未提交改动。
- 已认可的演奏基线是 [audio_core_v2](../../project/audio_core_v2/README.md)：钢琴0、Warm pluck2、铃音3、Drive lead4、自定义四谐波5；四种谐波音色共享32槽、拨弦物理池12，总数含尾音≤32。不偷音；谐波每音固定为V1的1/4，拨弦不变。
- 直接复用[音频接入包](../../project/audio_integration/README.md)：源码清单、状态/PCM/命令跨域桥、精简解包器和mock。接口优先级为[音频V2](../interfaces/AUDIO_CORE_V2.md) → [传输](../interfaces/AUDIO_TRANSPORT_V1.md) → [导入](../interfaces/AUDIO_IMPORT_V1.md)；V1只提供V2明确继承的字段/单位，SYSTEM_V0是历史参考。
- C额度不变：**13,000 Logic、10,000 Register、26 BSRAM、16 DSP、1 PLL**。公共音频传输桥已计入A，C新增UI、FFT、缓存、通信、曲谱和仲裁必须计入C。唯一总账是[团队预算](RESOURCE_BUDGET_V1.md)。
- 普通HDMI显示器已实测独立彩条1920×1080、约61Hz；这是DVI/TMDS视频，没有HDMI音频、触摸或自动EDID协商。复用[彩条探针](../../project/visual/dvi_colorbar_probe/README.md)；显示与音频尚未合并。
- C现在就能用mock做界面和协议，第一批成果应是可操作的画面、真实像素仿真图、接口缺口清单和资源报告，然后尽早与A做最小合并。

## 已有演奏逻辑如何反映到屏幕

现有底板S1短按切音色、长按恢复参数；S2短按普通延音、长按选择性延音；S4短按切旋钮模式、长按平滑止音。EC11调整当前参数，按压未确认。完整操作见[V1控制表](../../project/audio_core_v1/BOARD_TEST.md)与[V2说明](../../project/audio_core_v2/BOARD_TEST.md)。这是现有验证面板，成品映射由A/B一起设计。

| 音色/功能 | 屏幕需要表达的真实语义 | 适合的视觉设计 |
|---|---|---|
| 钢琴0 | 按下、踏板保持、松键尾音分别显示；释放和ADSR覆盖有区别 | 按键亮起、尾音小条缓慢退去，ADSR目标曲线 |
| Warm pluck2 | 一次触发自然衰减；按住不等于持续发声；延音/可调释放不强行生效 | 拨弦触发闪光或短波纹；不能把声部envelope=0画成无声 |
| Metallic bell3 | 击键后有自然音色演变；保留实际声部状态和旧尾音音色 | 小幅扩散光环、衰减轨迹；效果是装饰时标清 |
| Drive lead4 | 滑入、弯音、颤音、起音和房间效果已有控制 | 音高带、弯音中心线、颤音深度/速度；MIDI note字段不是逐样本实际瞬时音高 |
| 自定义5 | CH1～4实时改变四谐波比例，CH0是所有音色的独立主音量 | 四根谐波柱、目标/实际值、合成周期预览；推子接管状态 |
| 双演奏区 | 现有16白键为8+8；成品总两八度，逻辑25键为12+13，两区独立移八度 | 两块键区显示各自起始音名/八度，区分实体按键与仍在响的旧声部 |
| 切换音色/八度 | 只改变新击键；旧尾音保留原音色/实例和音高 | 顶部显示“新音色”，旧音仍按各自音色着色；不能整屏重染或清空 |
| 主音量/推子接管 | 远端、本地、推子共用参数服务；目标提交后还会平滑；ADC尚未实接 | 主音量目标和实际值，未接管提示；未提供实体推子位置时不能伪造实时位置 |

五音色ID不能压成0～4。Warm pluck的声部包络字段不适用；其尾音可显示occupied，装饰衰减不能标作实测响度。真实峰值目前来自最终混音窗口，不能分摊成每个音符的实际音量。

## 希望达到的产品效果

演奏者无需记住“旋钮现在在第几种模式”。屏幕应让人看懂当前参数、正在弹什么、哪些旧音因踏板保持，并能通过简单操控进入调音色、看声音、练曲三类活动。界面离线可用；切页、冻结波形、蓝牙重连都不打断发声。

下面三个布局方向平等开放，C可画两份草图比较后选一个，也可组合。**页面数不必等于同时常驻的硬件模块数，绘图和分析资源应复用。**

| 方向 | 观感与操作 | 优点/取舍 |
|---|---|---|
| A：演奏主屏＋工具页（推荐起点） | 主屏保留音色、双区、踏板和当前旋钮；切到音色编辑、声音分析、练习页 | 主屏易读，功能可逐页扩展；共用字模/绘图器，资源最可控 |
| B：三张卡片仪表台 | 主屏并排“演奏/声音/练习”小卡片，旋转选择、按下放大、返回缩回 | 一眼有整体状态，更像成品控制台；必须限制同时更新的小图数量 |
| C：舞台模式＋设置抽屉 | 大面积音符带/声音轨迹，少量关键状态常驻；按下唤出参数栏 | 视觉个性强、远看清楚；设置不能盖住故障/静音提示，动画须有简化开关 |

优先做三种低成本的新意：**音色色彩与声部尾音对应、四谐波“声音雕刻”、按键/谱线与节拍联动**。以矩形、短线段、少量查表曲线实现节奏和动感，比全屏照片背景更有演奏价值。动画更新可用帧计数器与短历史缓冲；不承诺大规模粒子、透明叠加或全屏长残影。

## 功能页的明确目标

### 1. 演奏控制台：首版必须做

- 常驻五音色名称/ID、主音量、静音、两个音区、普通/选择性延音、当前旋钮功能和值；启用房间效果时显示开关和湿声量。
- 两区键图对应当前实际映射。按下、踏板保持、释放尾音至少三种可区分样式，兼顾文字/形状，不能只靠颜色。声部容量显示“总数x/32、拨弦x/12”，达到上限时提示新击键被拒收，不误称自动偷音。
- 参数可由现有面板、本地UI或蓝牙改变，画面最终跟随音频的ACK和真实状态；冻结图形时状态栏仍继续更新。
- 简要异常提示覆盖鬼键/输入阻塞、削波、音频计算超时、观察数据中断、蓝牙状态；详细计数放诊断页。旧sticky告警不能动画闪到像新故障，标明“曾发生”。
- 建议状态反馈≤50ms（基于约47Hz快照和帧边界），需实测输入到屏幕可见变化的延迟。已捕获的按键短闪可适当保持60～120ms便于观察，但快照漏掉的短击键无法靠延长动画恢复；这属于视觉设计目标，不替代≤5ms模拟发声延迟指标。

### 2. 音色编辑：最值得突出特色

- ID5显示基频/2/3/4倍频四柱，并区分请求值与实际归一化/平滑后的系数。默认有效Q8系数 `[256,64,32,16]`；四路全推满也不能画成四路均保持256，实际总系数受368上界约束。
- 显示一周期的数学合成预览，可由C低速共享计算；标为“按系数计算的形状”，真实发声波形仍取DAC前PCM。若资源不足，先做四柱与真实波形，不再复制一套音频引擎。
- ADSR用示意曲线和有单位的参数；当前A/D/R是幅度码/采样帧，不应直接把原始码标成毫秒。若换算时间，声明满幅/起始电平假设。参数影响新音还是持续音须提示。
- Lead页突出滑入、弯音和颤音；Warm pluck页将不适用的延音/释放控件置灰并提示“自然衰减”。先不强求每种音色都有相同的编辑项。
- 可选2～4组用户四谐波预设，开销小，但存放位置、逐参数ACK、按住音时载入行为要先定义。当前配置不支持原子多参数提交；不能把逐次写入宣称为瞬时原子换预设。断电保持另议。

### 3. 声音分析：争取完整覆盖可视化条目

- **波形**：稳定触发、时间范围/幅度缩放、暂停查看；长时间范围用每列min/max保留瞬态。自动缩放时显示比例，音量比较可固定比例，避免静音噪声被无意放大成满屏。
- **频谱**：至少1024点FFT候选、窗函数、频率刻度、幅值相对刻度；约15～30次/秒刷新即可。Fs约48,076.923Hz，1024/2048点间距约46.95/23.48Hz、采集时长21.30/42.60ms。低音相邻半音不保证分开；长窗与显示响应权衡由C测试。
- **李萨如**：实际L/R PCM做XY图。干声相同就是直线，房间效果产生声道差异时可有展开，不能保证每段音都出现漂亮闭合曲线。延迟相图可另作艺术视图，但标名，与真实L/R页区分。
- 波形、频谱、XY可以切子页复用RAM；不要求首版三幅高分辨率图同时常驻。测试清晰覆盖单频、双频、静音、溢出和PCM缺口；FFT缺口丢弃当前窗口再对齐。
- 现场32频率演示需A提供频率间隔足够、可独立核对的测试激励。不能要求普通相邻低音32键在1024点FFT上各现一个峰，也不能以32条UI声部条代替32个频谱峰。

### 4. 练习/曲目引导：拓展主线之一

- 先内置一首允许使用的短曲：选曲、开始/暂停/停止、速度、节拍、下一个音/和弦、当前小节/进度。谱面可选简化钢琴卷帘、节奏格、固定谱线加音符；首版不做完整自动五线谱排版。
- FPGA独立计时并生成逻辑键位LED提示；手机和电脑断开后仍工作。真实LED在B板上实现，屏幕画一排LED只能做无板替身，不能据此认定“脱机LED引导”已经验收。
- A/B/C明确曲谱音符到当前双区物理键的映射；同音在两区同时存在时指定目标区/允许集合。超出当前键区的音提示换八度/不可达，不能默默点错键。
- 可选“等我弹对再走”和“固定节拍练习”；准确命中/漏键/提前或滞后评分需带时间戳按键事件，现有快照可能漏短击键，第一版只做引导不伪造精准评分。
- 下载曲谱先完整校验再启用，失败保留旧曲；播放时不覆盖正在读的事件存储。双缓冲或停止后提交由C权衡。掉电后保留内置ROM曲，下载曲默认RAM易失。

### 5. 蓝牙/客户端：从有用的闭环开始

1. 优先能力查询、选音色、主音量、适用释放参数、状态回读及ACK/NACK；界面同步显示本地变化、连接/忙/失败。最小客户端即可，App形态由C按蓝牙模块兼容性决定。
2. 再实现在线曲谱下载、键位自定义配置。当前A只有双区MIDI基址配置，**没有任意逐键映射表命令**；任意映射需要版本化接口与A的实例松键适配，不能只在屏幕改标签。
3. 尽量争取演奏录音回传，但单列可行性验证：事件日志回传有用，命名为“演奏事件记录”；官方“录音回传”按真实PCM音频目标另验收。事件记录不能代替PCM录音，也不能将预录音频回灌FPGA冒充合成。
4. 实际PCM单声道约96.15kB/s、双声道192.31kB/s，UART 8N1仅样本就需约0.962/1.923Mbaud，尚未加协议。115200不够；蓝牙模块的波特率上限也不等于实际空口吞吐。26块BSRAM理论总字节仅约58.5KiB，且已分配给多项功能，不可能同时当作长录音存储。
5. PCM回传优先评估稳定持续传输到客户端存盘；短缓存仅吸收抖动。降采样录音须先低通且标明实际采样率，压缩/外存另报资源。做不到时明确未覆盖该可选项，不牺牲本地实时声音。

## 屏幕交互与第二只编码器

普通电脑显示器不会经现有HDMI线返回旋钮/触摸输入。建议先定义UI事件 `nav_delta / confirm / back`，由C在TB/mock中驱动，实物来源随后由A/B安排。字段单位、队列和复位行为由C提案，不在本轮冻结RTL接口。

带独立按压开关的编码器适合“转动选页/选项 → 短按进入或确认 → 转动改值 → 短按退出编辑；长按返回”。页面导航和音量旋钮分开，可避免演奏中误改音量。菜单深度尽量≤2，状态栏注明“浏览/编辑”；全局止音保留独立可靠操作，不藏进菜单。快转可对长列表加速，音色和开关类选项不跳过确认。

资源预计导航/去抖/菜单状态机约数百Logic、0～1 BSRAM、0 DSP（未综合）。新增两相＋按压通常3个数字信号；若按压并入控制扫描，直接信号可为2。全部从B控制板/输入总账分配，含上拉、去抖与3.3V电气核对，不能随便拿走C蓝牙预留脚。现有EC11悬空C脚及按压未确认，**不得直接当作这只新编码器的按压端**。也可先用三独立键验证，无需立刻购买。

屏幕改音频参数和蓝牙改参数必须共用C侧命令仲裁/队列，再进入唯一`audio_command_bridge`。不能让两个模块驱动同一个host口。持续推子更新可合并最新绝对目标，已握手事务不得覆盖；panic/确认等事件不能作为普通旋转队列项随意丢弃。图形设置（缩放、页码、主题）留在C内部，不占用音频参数地址。

## 接口能提供什么，还缺什么

| 数据/操作 | 已有入口 | C需要补齐或向A提出的部分 |
|---|---|---|
| 完整状态 | `audio_snapshot_bridge`，当前46×64bit记录；能力表、基础状态、32声部、扩展、keys一致传输 | C在帧边界接纳，解包版本/长度校验；不能当UART固定包格式 |
| 首屏状态 | `audio_state_view`含音色、主音量、踏板、峰值、键图、声部note/preset/held/gated/occupied等 | 模式/音区/谐波/ADSR/效果/接管/包络/sostenuto逐声部等需从完整记录扩展解包；现成精简模块不包含全部字段 |
| 真实波形/FFT/XY | `audio_pcm_bridge`，最终效果与主音量后、DAC前，signed16 L/R＋sample_index32，约48.077kHz | PCM独立消费缓存；gap/session后重新组窗，不反压音频；不是模拟输出录音 |
| 配置写入 | 唯一命令桥，5bit地址、32bit值、tag、真实服务ACK/NACK | C仲裁UI/无线请求，去重、超时/重试/断连，读状态确认实际平滑值 |
| 精确按键时刻/完整演奏记录 | 目前没有给C的可靠逐事件流，约47Hz快照会漏短击键 | 向A提案带时间戳key_id/token/note_on/off事件、溢出计数/恢复；不拿快照差分宣称无损 |
| 当前实体推子位置/遥测 | 当前快照有参数目标、有效系数和接管标志；物理ADC未接 | 未接管时的真实原始位置不保证在现有快照中，若要显示“向上推到目标”需新增实采遥测 |
| 任意键映射/曲谱LED | 有双区基址，无任意映射或最终LED总线协议 | C做曲谱/UI和逻辑LED帧；A补事件映射，B补灯/驱动/布线；接口需版本化 |

关键单位以[参数服务](../../project/audio_parameter_lab/SPEC.md)为准：主音量Q16 0～65536，谐波实际Q8，谐波命令是raw12 0～4095，弯音每格1/4半音、范围±2半音，效果mix Q8 0～128表示0～50%。滑音/释放是索引而非毫秒。volume百分比只标“数字增益”，不要宣称线性响度；本地24档也不是24%。

## 资源可行性：按额度选效果

下表是**建议目标分配，非已综合数字**，完整C实现仍必须满足13k Logic/10k Register/26 BSRAM/16 DSP/1 PLL；替代原预算的子分区建议，不与原表重复相加。公共桥仍按A总账计。IP的位宽/端口模式可能浪费RAM，不能只用字节理论值保证可放下。

| 子项 | Logic目标 | Register目标 | BSRAM | DSP | 可争取的效果 |
|---|---:|---:|---:|---:|---|
| 视频输出、字模、菜单、状态解包、波形/XY小缓存 | 4500 | 3000 | 8 | 2 | 多页UI、双键区、四谐波柱、峰值条、稳定波形、低分辨率XY |
| FFT、窗/系数、工作区与结果 | 4000 | 3000 | 12 | 12 | 1024点分时FFT、15～30Hz显示；2048点先测资源再争取 |
| UART/协议、UI与蓝牙命令仲裁 | 2000 | 1500 | 2 | 0 | 调参回读、分包校验/去重、曲谱下载，不含长PCM存储 |
| 曲谱/引导/逻辑灯帧 | 1500 | 1500 | 4 | 0 | 一首内置＋有限下载事件，节拍/进度、简化卷帘 |
| C内部运算/布线余量 | 1000 | 1000 | 0 | 2 | 定标和实现余量；RAM须在各项中实留空间 |
| 合计 | 13000 | 10000 | 26 | 16 | 视频PLL最多1；需资源与时序均通过 |

可行性的量级依据：

- GW5AT此类BSRAM按18Kbit理论算约2304字节/块。1080p RGB888全帧约6.22MB，远超C预算；即使320×180、4bit索引色单帧也需28,800字节、理论13块，首版不选全帧缓存。推荐逐像素图元/字模＋小图块与线缓存。
- 128个8×16单色字形约2KiB，可先用短英文/图标/数字；中文可离线裁剪少量必需字，避免整套字库。图形模式切换复用字模ROM。
- 512列波形每列16bit min＋max，双缓冲约4KiB、理论2块；128×128单色XY双缓冲约4KiB、理论2块，再加字模和状态，8块显示额度有探索空间。更大XY密度/多级残影增加存储，要与波形复用或降分辨率。
- 示例1024点16bit实虚复数双工作区8KiB，半周旋转因子2KiB、窗2KiB、双频谱结果约4KiB，合计约16KiB，理论8块；12块为位宽/端口碎片预留。实际FFT需要的位宽、缩放、溢出和IP配置决定最终占用。2048点相似结构接近翻倍，不能默认12块够。
- 四块曲谱RAM理论9KiB；若事件8～12字节，且其中两块留作接收/影子缓存，单曲约384～576事件，实际还扣元数据。重复小节/离线转换可提高容量，不能承诺任意长歌曲。
- 多页、四柱、闪烁焦点、平滑电平条和少量音符短历史一般比额外FFT/大位图便宜；优先把资源花在上述可解释的动态反馈。

当前A保留接口审计已占31,075 Logic/15,790 Register/64 BSRAM/24.5 DSP，50MHz余量只有0.076ns。加C全部额度的规划算术为44,075/25,790/90/40.5，容量有余但**时序并不保证**。像素域约150MHz的绘图还需自身收敛；不要在一个像素周期堆大量乘除法。可考虑低分辨率内部坐标放大到1080p，或在目标显示器复测720p。正式整机要统一Bank5、Y12、所有时钟/CDC约束后重跑PnR。

官方IP优先评估PLL、BSRAM/ROM、FFT及必要FIFO；需提交配置、工具版本、仿真模型和重建方法。FFT是否适配器件、资源/位宽/缩放、吞吐均须实测；不因为叫IP就视为自动省资源。已有公共CDC桥不重复复制。

## 接下来约两周的设计目标

这是一份依赖顺序，工作日按实际进度调整；硬件采购/板卡预约由团队安排。

| 阶段 | 目标交付 | 可验收结果 |
|---|---|---|
| 第1～2工作日 | 两个屏幕草图；页/导航事件；字段与缺口表；基于mock的第一屏；蓝牙候选/客户端兼容性和带宽计划 | 可看出浏览/编辑、五音色、两区、踏板和尾音，至少一帧由真实RTL渲染导出；记录初次资源 |
| 第3～5工作日 | 主屏＋谐波编辑视图、共享命令入口；UART模拟字节流调参回读 | UI请求→ACK→真实状态的测试闭环；坏包/重复包/断连不会改坏参数；与A尽早合并最小状态屏PnR |
| 第6～8工作日 | 波形＋1024点FFT＋低成本XY；参数冻结/缩放；原始数据来源测试 | 已知频率/幅值、L=R直线、PCM缺口重组窗口；统计C资源和音频截止时间，不延迟声音 |
| 第9～12工作日 | 内置曲目/节拍/LED逻辑帧；下载事务；定义逐事件与键位映射缺口 | 断开客户端仍引导；模拟灯或无板测试明确标记；与B接真实LED后再记实物通过 |
| 之后按资源收尾 | 录音带宽实测、可选2048FFT/残影/用户预设、外观优化 | 达成的附加项有证据，未达成的从演示承诺中剔除 |

第一阶段不需要等A写更多音色或B完成PCB。C交付方案即可决定采用哪种布局；实现路径可迭代。每阶段提交源码/IP配置、生成脚本、渲染图片或视频、测试命令、资源/时序、数据来源和未验证项。现有接入包三桥与干净导入/消费者测试通过；完整核心联动有旧同RTL指纹PASS，本轮ModelSim重跑停滞，详见[验证边界](../../project/audio_integration/VALIDATION.md)。

开始实物合并前，A/C统一[TMDS球号、电气和复位](../board/DISPLAY.md)，A/B/C统一导航旋钮/ADC/LED针位。明确“冻结图像只冻结图像”“通信阻塞只影响通信”“音色切换不误删尾音”，再做整机资源、50MHz/像素时钟和板测。

# B：实体操控与控制板

你负责“人怎样顺手演奏”的整个实体控制部分：交互方式、键区布局、传感器与旋钮/踏板、原理图/PCB、IO提案、线束、电气与机械配合。主目录[hardware/interaction](../../hardware/interaction/README.md)。不要求你先读懂音频算法；输入RTL由团队逐项明确负责人。

**当前开工依据（9月26日）：** [团队预算V1](RESOURCE_BUDGET_V1.md)，重点读第2、4、5节。B常规目标10根、上限12根PMOD信号；C蓝牙预留4根。通过移位寄存器/多通道ADC扩展键与连续轴，布局由B设计；输入适配另预留3000 Logic、2 BSRAM、2 DSP，作者逐项约定。音频独立开发，B不用等待音频新功能完成才做小样。

9月19日A已在任务分支提供[逻辑输入候选](../../project/input/README.md)，含矩阵/EC11/压力后处理及故障恢复；这不冻结你的最终交互。先重点确认有无逐键二极管、行列/电压/连接器、EC11每格相位和压力分压/ADC需求。输入模块后续维护归属仍逐项约定。

当前[双音色演奏版](../../project/final_dual_timbre/README.md)已获用户板测认可：4×4接PMOD1/J8、EC11 T18/R17、三板载用户键。此前[矩阵演奏候选](../../project/input/matrix_playable/README.md)提供接线和扫描参考；现有无二极管矩阵不能识别任意多键和弦。成品若采用逐键二极管，A/B需同步调整并验证鬼键策略。拨弦自然衰减；本轮计划恢复选择性延音、增加滑音，尾音控制只用于适合的音色。

## 已知约束

- 当前只有一块Tang Mega 60K＋NEO Dock。外接4×4和EC11已到，EC11独立变调板测通过；FSR实物/采样链验收待确认。它们用于验证，最终布局未定。
- 琴键和网格平等考虑。有人会弹琴是试弹资源，不是“必须做电子琴”的决定。
- 基础至少2个独立演奏维度，拓展≥3维。全局FSR压力不是逐键力度；普通按键不天然测击键速度。演奏时不能为找音量/压力控制而不断离开主键区。
- 低延迟、可按和弦、无卡音、松键自然、有触觉反馈比先画漂亮PCB更早验收。
- 不能默认所有GPIO/ADC都是3.3V。PMOD2×6、4×4一排8针需正确分线，见[IO表](../board/IO_RESOURCES.md)。

## 首轮可立即开展的任务

1. 做两份交互草案，例如琴键＋脚控、固定音程网格＋拇指表达，也可提出更合理方案。画出两手位置，说明选音、和弦、力度/连续表达、音色/音量、延音、移调及紧急全释放怎么操作。键数和布局写候选，不先锁死。
2. 用纸板/现有模块试弹一段单旋律与和弦，记录换手、误触、跨度和表达是否打断节奏；选型表包含演奏性、成本、采购周期、IO/ADC、加工难度。
3. 对已购模块查清引脚、供电、开关矩阵是否有二极管、EC11上拉、FSR规格。提交[IO提案](../../templates/IO_PROPOSAL.csv)和接线图，由A/C一起排除冲突。
4. 交付原理图草案、BOM候选、连接器与机械尺寸；确认接线后做低风险小样。正式投板是后续单独动作。

## 交付给A/C的内容

每个控制信号的物理含义、有效电平、最大更新率、去抖/校准需求、默认态、断线处理和连接器针号。建议给原始输入序列或CSV，方便无板成员做testbench。按键松开必须可靠，持键切八度后仍释放原音；两个物理键映射同音需定义计数/归属。

演奏指导LED由C定义曲目/提示语义，B安排灯的位置、驱动电路和供电；灯驱动RTL归属也要写清。后期外壳3D打印需预留USB、电源、耳机、HDMI、固定柱和散热，别只按主板外形圈一个盒子。

首个分支可用`feat/b-interaction-proposal`，不依赖A先解决音质。PR交付两份布局、IO表、待定项和小样验收计划即可，不必第一天完成PCB。

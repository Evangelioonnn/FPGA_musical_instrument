## 判断与已知基线

八声部三音色、两种延音、DDS音色滑音/弯音、力度/压力表达、适量数字效果器和程序绘图，有可行的资源路线。优先整理重复 ROM 和逐声部运算；不需要因为彩条成功就换更大芯片。16/32声部必须作为架构扩容任务，不能直接复制现有完整声部。

用户此前已确认 `final_dual_timbre.fs` 的音频与控制效果较理想，是音频方向第一版完整演示；旧文档的“尚未板测”已过时。此反馈不等于板卡模拟噪声根因已排除。显示彩条另有实测：1920×1080、显示器报告61Hz，稳定；音频与显示仍未合并构建。

音频 STA：50MHz，setup/hold 最差报告余量3.473/0.191ns，违例端点0/0。彩条实际像素时钟150MHz、串行器FCLK 750MHz，DDR发送数据每通道1.5Gbit/s；总时序2200×1125，帧率约60.606Hz。音频Fs=50MHz/1040≈48076.923Hz，每帧有1040个系统时钟（20.8µs）。

`LW=8/8` 不表示八个独立时钟已经用满：报告中的多数LW网络是每声部 `voice_rst` 及其他高扇出控制信号。须检查复位扇出/自动路由分配和合并后的时序，不能把两个独立实现的LW数字直接相加判超限。

还发现一个集成前需处理的具体约束差异：音频J16状态LED在报告Bank5按3.3V约束，彩条K17/J17同属报告Bank5却写2.5V。彩条成功证明当前引脚链路可显示，不证明CST中的2.5V就是实物供电。合并前需沿板图/器件规则统一这些电气属性；本轮没有改CST。

## 存储与运算开销来源

`final_slot` 每个声部都实例化 harmonic 与 pluck 两套算法，只在输出处选择音色；选择菜单不会释放另一套已综合电路。

- harmonic：每声部四份1024×16正弦表，八声部32份。综合层级明确为32块BSRAM、8个MULTALU27X18。四个谐波从同一相位推导，不能直接宣称为四个完全独立可控振荡器。
- pluck：每声部1024×24状态RAM（两块SDPB），八声部共16块。它保存物理模型状态，不能删除或让不同声部覆盖。
- pluck起音参数：每声部还复制length/fraction/reciprocal查表。综合网表中每声部两个32位pROM，PnR的总pROM为64；这类起音只读参数有共享或逻辑查表的优化空间。
- 综合报告合计64块BSRAM，而PnR是80块；必须按后者预算，不能用综合前映射数字替代实际落地开销。
- 既有harmonic-only/ pluck-only探针的音高是常量，拨弦参数表会被裁剪，不能据其16块BSRAM就说完整拨弦也只需16块。

建议先做保守共享：八声部共用四个正弦ROM读通道，保持原相位、四分量权重、ADSR和数值舍入，理论表数量32→4，减少28份。**这是架构预期，未在harmonic终版验证**；若其他映射保持，音频BSRAM可从80降到约52，为新增功能释放空间。再共享拨弦起音参数表，保持各声部独立状态和起音初始化时限。

可复用证据：`resource_optimization_lab/VALIDATION.md` 中完整共享正弦八声部候选为3894 Logic/2277 Register/1 BSRAM/2 DSP，624帧与旧正弦参考逐样本一致，PnR通过。它没有验证四谐波、拨弦或第三音色，也未板测；不能把这组数字直接当终版预测。

## 新功能预算

以下为设计预留范围，全部不是新构建实测。基于八声部、小型控制器、时分共享运算、没有完整帧缓存；实际数据宽度、端口、IP参数及综合映射会改变开销，重叠的共享资源不能重复计数。

| 功能 | 建议增量预留BSRAM / DSP | 路线与主要限制 |
|---|---|---|
| 第三音色：笛/管风琴方向的持续加法音色 | 0–4 / 0–4 | 与harmonic共享正弦表和运算，增加系数/包络预设；先用低阶谐波试听，不承诺真实乐器建模质量 |
| 选择性延音 | 0 / 0 | 每声部捕获标记、边沿检测和释放条件，少量寄存器/逻辑；按下时捕获held实例，清理和重用时必须清标记 |
| DDS音色滑音、持音实时变调 | 0–2 / 0–4 | current/target相位步进、速度与可选音分映射；简单线性步进可不用DSP，按音程平滑/弯音比例另计 |
| 完整ADSR、力度与压力表达 | 0–2 / 0–4 | 参数寄存器、平滑、共享增益乘法；独立物理控制维度由B交互决定，不以菜单数量代替 |
| 颤音/震音 | 0–1 / 0–2 | 小型LFO复用相位/幅度控制；支持关闭，默认不调制 |
| 全局轻量合唱（约10–30ms，16bit延迟状态） | 2–4 / 2–6 | 共享短延迟线、插值、LFO和干湿混合；以映射后容量为准，点击/饱和需验证 |
| 小型算法混响（替代或后续增加） | 8–16 / 4–12 | 总延迟线长度决定存储，反馈稳定和精度需测试；避免卷积混响首发 |
| 键位/音量/音色/波形等程序绘图 | 4–12 / 0–4 | 字模、采样快照、CDC与少量缓存；不放全屏RGB照片 |
| 256/512点时分复用FFT频谱，单独增量 | 4–12 / 4–12 | 原始全速PCM、窗函数、定标、分帧；官方FFT具体配置须实际综合，不能保证落在此范围 |
| LED曲目指引、少量事件曲谱 | 1–4 / 0 | 时间戳/音符事件序列、节拍和按键匹配；不是简单亮一个状态灯 |
| 蓝牙配置、键位映射、曲谱下载 | 1–4 / 0–1 | 假设模块承担射频、FPGA实现UART/SPI及协议/FIFO；含校验/队列/断连处理 |

选择性延音和普通延音延长的是声部占用，不是大块音频存储。8个声部若全部被保持，后续新音仍会被拒绝（当前策略保护旧音尾音）；扩容和“满声部如何处理”必须一并讨论，不能承诺有限硬件下任意多音都完整保持。

滑音首发建议用于持续第三音色的单音连奏模式，并为DDS音色提供平滑弯音。当前 `clean_voice.step_hold` 仅在note_on锁存，最终版尚无持音更新接口；必须实际连通频率更新，保持相位连续，不能只修改音号元数据。拨弦依赖环形延迟长度/分数延迟，不能照搬DDS滑音；先保持当前自然衰减。

## 官方指标逐项落实

1. **基础交互≥2独立维度，拓展≥3维**：自研演奏面+压力/力度+弯音/滑音控制等可形成方案。FPGA数字处理成本低，难点在传感器位置、电气、采样、标定和演奏手感。一个旋钮切三个菜单不自动构成三个独立同时可控维度。
2. **基础≥4独立声部、实时变调、ADSR、混音、≤10ms**：八声部已提供数量基础。当前final版A/D/S固定、R可调，需把其余ADSR参数及持音变调接到控制；实测完整触发到模拟输出延迟。已有旧矩阵约1.8ms数字案例不能替代当前端到端测量。
3. **拓展≥2乐器音色与数字效果器**：第三音色是产品选择，官方不是强制三种。普通/选择性延音改变包络生命周期，不把它们等同于原文混响、延迟、合唱等效果器。用户此前暂缓回声，本轮优先建议可旁路轻量合唱，混响视听感和剩余存储再加，不恢复已搁置回声为默认任务。
4. **拓展≤5ms确定性延迟和FPGA视听反馈**：数字逻辑成本低，但要统计真实输入扫描/去抖/帧调度延迟分布，并定义测量触发及输出阈值；异步输入可能有量化差，不能把恒定计算周期宣称绝对无抖动。显示/FFT/蓝牙必须旁路采样，不能反压发声。
5. **LED/波形/频谱/李萨如**：按原文逐项记录覆盖情况，不假定彩条等于可视化指标验收。当前L/R同值，真正L/R李萨如是直线；声部分路、立体声输出或带标识的延迟相图都需定义信号含义。
6. **脱机曲目指引与蓝牙**：事件曲谱对存储友好。事件演奏记录需明确与PCM录音不同；若做16bit单声道原始PCM回传，当前采样率约96kB/s（约0.77Mbit/s净荷），UART起止位/协议另加，不能默认115200波特率足够。双声道或长时间缓存成本更高，应单列任务。
7. **高并行扩展**：原文为≥32复音，或单音≥32加法分量，或多条并行物理模型。已有八路pluck具有并行模型基础，应补足多路独立可闻及频谱证据，但不提前宣称高吞吐评分已达最优。
8. **评分与测试模式**：不同音色菜单数量不等于同时活跃振荡器数；四份相关谐波查表不能简单乘以声部数宣称32独立振荡器。若争取32分量，保留独立相位/频率/包络和测试配置、避免谱峰混叠，证明同时活跃可闻。吞吐按实际Fs而非视频时钟或额外过采样计算。
9. **输出接口口径**：原文写I2S；现有PT8211为LSBJ格式。必要时与赛方确认用词，或增设标准I2S DAC接口作为合规备选；串行器通常仅少量逻辑、不需要大量BSRAM/DSP，不为名称而破坏当前正确电气时序。

## 高复音与存储上限

按当前8个同构双音色槽估算，16路约需160 BSRAM、113 DSP，32路约需320 BSRAM、225 DSP（都未构建；优化会改变结果）。这条复制路线超过存储预算，32路还超过DSP预算。

推荐先做8路功能完整，再挑战16路产品复音；32路选择共享表/乘法的DDS或多通道加法路线，保留可独立调度的拨弦模型池。若限定“DDS声部多、拨弦声部少”，这是可闻功能约束，须明确交互与各音色复音上限，不能伪称所有音色都有32复音。旧capacity32曾在50MHz失败，不能作为已完成实现。

每音频帧1040拍允许多个并行流水引擎各自复用运算：32路×4谐波=128次查表/帧，有调度探索空间，但ROM读延迟、包络、混音、同时起音的拨弦初始化及事件队列均要计入最坏截止时间。不可只用平均吞吐推断达标；“FPGA内部有界时分调度”也不等于软件串行合成。

频谱建议先做512点验证接口（约93.9Hz/bin，低音相邻半音分不开），再按展示和赛题谱峰验证需要选择1024/2048点或正确低通降采样。512点不是音准分析的最终承诺。FFT窗口只影响视觉更新，不能增加演奏音频延迟。

显示无需全帧RGB存储：1080p×24bit约6.22MB/帧。可用程序绘图、字模、小图块、波形缓冲；不是规定显示不得使用任何BSRAM。必要时外部存储是可选路线，但会增加控制器、IO与时序工作量，当前不作为首选。

## 第一阶段建议资源上限（团队讨论稿）

以下是给各模块的设计目标，不是对C的冻结接口或已经得到的综合结果，范围为八声部三音色产品路线：

| 分区 | BSRAM上限 | DSP上限 | Logic预留上限 |
|---|---:|---:|---:|
| 优化后音频核心+三音色+演奏控制 | 56 | 64 | 22000 |
| 一套受控规模效果器 | 12 | 12 | 4000 |
| 程序绘图+采样/CDC+小型FFT | 24 | 16 | 10000 |
| 蓝牙+事件曲谱/LED控制 | 4 | 2 | 3000 |
| 合计预算 | 96/118 | 94/118 | 39000/59904 |
| 保留余量 | 22 | 24 | 20904 |

若官方IP实例超过上述预算，先比较共享架构/配置再调整分区；逻辑百分比、BSRAM、DSP、PLL/布线和真实IO都是独立约束，不能取平均使用率。16路/32路另开预算，不能直接套用此表。

实施顺序：

1. 保留板测基准，在独立资源工程共享正弦表和拨弦起音参数；逐样本等价、同时起音、保持/释放和截止回归通过后再迁移。
2. 接入第三持续音色、两类延音、持音变调/滑音、完整ADSR和力度表达，维持8路；验证选择性延音占满声部时的实际策略。
3. A/C做最小音频+显示集成构建，统一Y12用途、Bank电气属性、复位、PLL与CDC。再分别加入效果器、FFT、蓝牙并更新预算。
4. 按效果与资源实测选择16路产品扩容及32独立振荡器/分量的评分验证路线；用户验收音质，不靠降低音量/采样率冒充优化。

官方IP适合用于器件PLL、双口RAM/ROM、真正异步FIFO、DSP流水和FFT；`FIFO_SC`是同钟FIFO，不能作为跨域FIFO使用。DDS II可评估多通道复用，但其通道不是完整乐器声部。封装现有RTL或换成IP名称本身不会节省资源。

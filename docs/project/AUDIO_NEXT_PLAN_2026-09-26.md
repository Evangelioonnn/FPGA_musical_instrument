# A音频下一阶段方案 · 2026-09-26

本轮为方案与只读审查，不开始实现、综合或生成新固件。角色A；阅读基线`6f904f3`，记录分支`codex/resource-feature-budget`；范围为本规划和STATUS。依据当前源码、既有用户板测、[团队预算](../team/RESOURCE_BUDGET_V1.md)与开源源文件。后续实现另开音频任务分支，并保留已板测final_dual_timbre。

## 用户本轮决定

- 总共两个八度的琴键区，分两个区，各区独立选择所处八度。不是每区两个八度；24音级与补最高C的25键形式交B按实物方案决定，音频接口应兼容。
- 增加选择性延音和滑音，效果适用性随音色定义。原拨弦保持自然衰减，不强制踏板保持或DDS式滑音。
- 继续以软件/RTL寻找更干净音色，保留拨弦；重点改善钢琴风格，探索带效果的电吉他风格。暂不把进实验室作为本轮工作的先决条件。
- 可以只对一种音色提供更高复音；至少完整保留C已分配预算。

## 1. 先区分音域、物理键数与复音

当前`playable_keys.v`把16键写为MIDI60–75；`final_bank.v`允许48–84；`final_dual_top.v`实例化8声部。扩大可选音域主要增加映射/配置状态，不需要每个可选音高常驻一个发声单元。

首版两个区各12个半音，例：左C3–B3（48–59），右C4–B4（60–71）。左区可独立换到C2–B2，右区不变。若B采用25键，最高端点C归右区额外一键；不擅自增加物理琴键数。

接口使用物理key_id、zone_id、zone_base、实例token；在输入事件进入队列时锁定当时配置。切换八度只影响后续起音，已有音保持，松键始终释放原token。两区同音高仍是两个独立实例。连续弯音与八度选择是不同操作，不能换八度就自动滑动全部旧音。

| 音源 | 建议首轮音域 | 依据与扩展代价 |
|---|---|---|
| 现有/改良拨弦 | C2–C6，MIDI36–84，先按此验收 | 底层参数表和合法范围已有；管理器需开放36–47，逐音高验收，不增加现有1024深度状态RAM |
| 钢琴式DDS/持续DDS | 先与拨弦共同覆盖36–84，再验收24–96（C1–C7） | note_table已有0–127；真正限制是高低音听感、谐波频率和参数范围，不是表里能否填音号 |
| 拨弦后续高音 | 85–96候选 | 补参数与边界检查，验证短延迟线音准/阻尼/音色后决定 |
| 拨弦更低音 | 暂不承诺C1 | C1在当前Fs需约1471点延迟，1024不够；2048深度会增加状态RAM、地址和初始化工作，八声部保守从16向约32块BSRAM预算评估 |

每区八度菜单只列该音色能完整覆盖的合法区间，弯音也需边界处理。MIDI号超界不得回绕、静默替换C4或产生越界地址。DDS高音时按实际频率减少越奈奎斯特的分量。

## 2. 资源先建立可复用结构

A继续守26000 Logic、14000 Register、68 BSRAM、76 DSP；输入适配另3000/3000/2/2。C保留13000 Logic、10000 Register、26 BSRAM、16 DSP、1 PLL及其接口额度，不借用C资源承诺音频扩展。

当前音频80 BSRAM/57 DSP尚未符合A目标。每槽同时实例化harmonic与pluck、再选择输出；复制到16/32槽会重复大量未同时使用的算法。首轮步骤：

1. 修正共享实验的参数化与超时监控，以8路原音逐样本等价为门槛。
2. 共享四谐波ROM读通道，再共享pluck仅起音用的length/fraction/reciprocal表；每条拨弦仍保留独立可变状态RAM。
3. 改为独立声部池：8路拨弦池+16路共享DDS池；在此基础上挑战32路DDS。不同音色共享DDS算术，保留每声部独立相位/包络/频率/身份。
4. 实测16路资源与最坏调度后，再选一种干净低成本DDS音色做32路；钢琴能否也32路以丰富音色实际运算量为准。明确各音色上限与混用总上限，不提前宣称“所有音色32复音”。

只共享四谐波表理论32→4份，可减少28块使当前80→约52；不是已构建结果。8路拨弦的1024×24状态RAM基线16块，不能删除。每音频帧1040个50MHz周期：32×4分量共128次查表，按每分量4拍已512拍；32×8若同调度已占1024拍，尚未包括包络/混音，因此需要流水/多读通道，不能无限堆分量。

本轮预检发现`resource_shared_sine_bank.v`：busy固定8项、sched_count仅4bit，且`if(sample_ce && !running)`内部再`if(running)`的deadline告警不可触发。这不否定原8路624帧对照，但不能用该监控作为16/32路截止证明。后续先修，再用独立TB统计每帧应有输出与最坏截止。

## 3. 音色与效果按演奏语义设计

| 候选 | 音色生成重点 | 普通/选择性延音 | 滑音/颤音 | 效果器 |
|---|---|---|---|---|
| 改良钢琴风格 | 干净基音、少量分组谐波；高次衰减快、基音慢，短起音；力度同时影响响度/亮度 | 支持；抬起阻尼的听感，声音仍自然递减，不把包络永远冻住 | 默认关；可作为合成钢琴实验开关 | 干声先过关，再轻合唱或小混响 |
| 原pluck与精度改良pluck | 保留物理模型；对比精度、激励带宽、阻尼、拨弦/拾音位置 | 首版都不强加，维持一次触发自然衰减 | 首版不加延迟长度突变；连续弦变调以后独立验证 | 自然干声优先，可选轻效果 |
| 电吉他风格/Lead | 先稳定干声；可用带限DDS近似快速验证，再评估弦模型细节 | 随预设决定，不能自动套用钢琴踏板行为 | 优先支持连续弯音、单音连奏滑音、可控音高颤音 | 轻过载→箱体风格滤波→可选合唱，均可旁路 |

钢琴先做“柔和”和“明亮”两套动态谐波/包络，A/B选一套；不以增加无限静态谐波冒充真实钢琴。初轮不加随机失谐/多弦拍频，防止与用户在意的颤抖混淆。由现有基准渐进改进，目标是干净、顺手、可演奏的合成钢琴，不承诺达到多层采样钢琴写实程度，也不以预录PCM替代合成。

滑音分两种：连续控制器弯音（先建议±2半音，再可调范围）和单音连奏portamento（先试约20–250ms）。后者先规定最后按下音优先、松开退回仍按住音、相位连续；多音和弦保持独立声部，不让所有声部自动滑向同一个新音。音高颤音与音量震音分别参数化、默认关闭，防止自然拍频被当成主动效果。

选择性延音在踏板上升沿捕获当时真实held的实例，之后新音不自动捕获。释放时综合普通踏板、选择踏板和真实按键状态；按音色能力决定是否参与。测试踏板交叠、同音不同实例、改八度、槽回收与panic，保留held/gated/occupied的区别供C显示。

“电吉他风格”可以先由DDS提供稳定持续音/弯音，后续STK弦模型提供更自然的拨弦细节；这两条路线的听感与成本分别验收。过载会主动产生谐波，干声合格后再加。非线性单元采用温和波形整形，必要时仅该效果内部局部过采样并滤波降采样，避免重度硬削波造成混叠。

效果器采用共享效果总线，不为每个声部复制混响/合唱。保留干声与效果输出单独监听，音色切换作用于新实例、效果参数平滑改变，不能切音色时突然清缓存产生爆音。合唱先按2–4 BSRAM/2–6 DSP探索；小混响约8–12块或更多，实测若超过A效果预留需取舍。两套效果不默认同时全开。延音/选择性延音自身不代替官方数字效果器指标。

## 4. 数字音质优化与验证

当前`final_slot`的pluck先右移5位并限到[-512,511]，`clean_voice`包络积右移19位。可探索保留更多中间有效位、在宽混音/增益后统一舍入到16bit；按相近听感响度对照，不能仅放大声音就说更干净。这是明确可试的改良点，不是现有杂音根因定论。

候选顺序：

1. 现音色数值路径：审计舍入、负数截断、饱和位置、查表相位精度；比较线性插值/增加表精度的资源与杂散收益。
2. 钢琴音色本身：时变谐波、起音/释放连续性、按音域调整亮度；干声单音、半音相邻/三度/五度/八度和弦分别分析。
3. 拨弦：保留原版，对比更高有效精度、滤波激励、阻尼和DC偏置；不把当前认可音色直接替换为重模型。
4. Lead：先干净持续音、弯音、滑音，随后过载/箱体滤波/合唱，检查每级新增频谱。

验证组合包含低中高音、极弱/正常/强力度、长尾/静音、密集重复同音、切音色、快滑音、满声部和踏板组合。用独立数学参考与实际RTL输出比对，检查谐波以外杂散、削顶/DC、尾部极限环和点击。必要时加入可关抖动量化作单独候选，不能默认提高静音底噪。

复音增多不按当前活跃声部数除音量，避免加一个新音让旧音变小；用宽累加、固定声部标定和输出余量。若总峰值超DAC范围必须有确定限幅/保护及clip证据，不能保证任意数量满幅声音叠加都无失真。首轮满声部继续拒绝新音、统计拒绝，保持原尾音；后续最轻释放声部回收作为可选策略，明确会截短尾音，不暗中改变用户偏好。

## 5. 已核实可借鉴的开源来源

- [STK Plucked](https://github.com/thestk/stk/blob/master/src/Plucked.cpp)、[Twang](https://github.com/thestk/stk/blob/master/include/Twang.h)、[StifKarp](https://github.com/thestk/stk/blob/master/src/StifKarp.cpp)：C++实时物理模型，MIT式宽松[许可](https://github.com/thestk/stk/blob/master/LICENSE)。适合分块重写定点RTL：激励、拨弦位置、阻尼、分数延迟。所选路径不依赖整段音符录音。
- [Rings弦模型](https://github.com/pichenettes/eurorack/blob/master/rings/dsp/string.cc)、[合唱](https://github.com/pichenettes/eurorack/blob/master/rings/dsp/fx/chorus.h)：所选文件MIT、C++。可借参数插值/滤波及共享短延迟效果；完整弦模型较重，不承诺整套移植。合唱的2048×16bit缓冲约4KB，至少2块18Kb存储量级，端口及映射后可能更多。
- [OPL3 FPGA](https://github.com/gtaylormb/opl3_fpga)、[核心RTL](https://github.com/gtaylormb/opl3_fpga/blob/master/fpga/modules/top_level/src/opl3.sv)：真正SystemVerilog，LGPL-3.0-or-later。36 operator不等于36完整声部；可用FPGA状态机控制寄存器，不引入示例ARM软件作为合成核心。需单独验证Gowin兼容、时钟/Fs、音色配置和资源；适合作经典电钢琴/风琴/吉他备选，不优先挤进当前主工程。

借开源算法不保证消除公共输出链的异常。所有新音色先WAV/RTL验收，再交用户同一硬件试听；不需要等待实验室才能继续这些工作。

当前4×4不能变成24个同时独立实体键。可以做8+8双区缩略或分页模式验证八度/保持关系，全24/25输入与16/32并发在独立TB/自动演奏覆盖；完整双八度手感和鬼键表现等B硬件后再验收。测试模式是临时工具，不用复杂菜单替代终版顺手操控。

推荐最先执行R1和P1，并并行准备T1参考音。先拿到资源更省、音域更宽的基线及少量干净候选，再加入适用控制，最后扩大复音并收敛完整版本。本轮没有开始这些实现任务。

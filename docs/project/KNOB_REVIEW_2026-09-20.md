# 9月20日旋钮任务：早上验收

先读本页即可开始。工程目录为[knob_suite](../../project/input/knob_suite/README.md)，证据和具体结果见[验证记录](../../evidence/knob_suite_2026-09-20/README.md)。新固件等待用户板测，不能将过去EC11持续变调的通过结论自动转移过来。

## 先验收逐格弹奏

1. 保持已验证接线：3.3V、GND、A=T18、B=R17、C悬空；不要接PMOD-LEDx8。耳机仍接3.5mm口。
2. 打开 `project/input/knob_suite/board/performance/knob_performance.gprj`，核对Top为 `knob_performance_top`。已有本机构建可直接使用对应 `impl/pnr/knob_performance.fs`，用原来的SRAM下载方式。
3. 上电/下载后先不转：应安静。转一格：应有一次完整起音、持键与尾音，约0.88秒结束。静止不会反复触发。
4. 每秒转一格，听升/降半音；再连续快转，听新音起音与旧音尾音重叠。来回两格，确认重复音高也有新起音，前一个尾音不会被切掉。
5. 停止后等待约1秒，声音应自然消失。请分别反馈“旋钮事件”“音符/复音”“原有尖锐附加声”，不要把公共音质问题和触发错误混为一个结论。

第一格的音高取决于方向：初始光标C4，正方向第一格C#4，负方向第一格B3。上下限C3/C6，到边界继续转会重复弹边界音。有限16声部；极快转动可能填满，系统保护已有尾音并拒绝新音，不是无限复音。

## 再逐项换固件

| 版本 | 下载后的声音 | 操作与通过标准 |
|---|---|---|
| `volume/knob_volume.fs` | 固定原音色音符，周期性四音和弦 | 一方向减到静音，再反向恢复；不改变音高，不重启整段序列。共有0..24档，端点不回绕 |
| `timbre/knob_timbre.fs` | 每约0.5秒一个自动音符 | 每格切换原音色、pluck、FM；等下一次新音听变化，之前尾音保留。FM原有杂音可能更明显，不据此直接认定切换失败 |
| `release/knob_release.fs` | 每1.2秒一次C4，固定持键0.2秒 | 改变尾音长短；默认约227ms，可约7..682ms。只影响下一次触发的音符 |
| `echo/knob_echo.fs` | 每秒一次短C4，默认无回声 | 一方向逐渐增加回声，再退回关闭；干声保留，关闭后不应把旧回声当作新音继续播放 |

表内文件都位于 `project/input/knob_suite/board/<版本>/impl/pnr/`；对应gprj在上一层，顶层都是 `knob_<版本>_top`。一次只改变固件，不更改接线。自动发声版本下载后就会播放，沿用原监测电平。

## 按压功能待确认

已有事实：C–VCC约9.9kΩ、C–GND超量程，按压读数未改变；A/B旋转已经实物验收。不能从这些事实推导C就是按键或公共地。

后续先看模块背面走线、编码器额外两只开关焊脚是否引出，再断开模块全部连线，测实际开关两端：普通机械常开按压触点应在松开时开路、按下时接近零欧。若没有独立触点或未引出，不依赖该模块按压；B可另设计可靠模式按键。确认信号与电压后再由A分配输入针位。

记录板测时注明版本、实际bitstream哈希、旋转方向、供电和耳机，分别写通过项与异常发生时刻。五个版本互相独立，某一项失败时保留其他验收结果。

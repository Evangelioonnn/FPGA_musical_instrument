# 旋钮演奏候选的接口边界

> 历史契约，仅用于本页对应旧工程。当前C对接先读[AUDIO_CORE_V2](AUDIO_CORE_V2.md)、[传输契约](AUDIO_TRANSPORT_V1.md)和[接口索引](README.md)；下文“当前/新”均指当时版本。

2026-09-20，A的独立任务 `codex/knob-performance-suite`。入口：[工程说明](../../project/input/knob_suite/README.md)、[规格](../../project/input/knob_suite/SPEC.md)。本页解释可以复用什么；不替换[SYSTEM_V0](SYSTEM_V0.md)，也不冻结B的最终交互方式或C的蓝牙协议。

| 层 | 已提供的能力 | 接整机前还要补齐 |
|---|---|---|
| EC11输入 | 现有去抖/Gray解码，每4相位转移一个卡点事件 | 更换模块时重新核实相位；实际按压端未知 |
| 参数映射 | 五个独立模式：弹奏、音量、音色、释放、回声量 | 实体模式按键/显示反馈、PC与本地配置所有权 |
| 独立音符 | 每次触发分配自己的声部；同音可重复叠加；定时松键 | 外部按键的instance/token→note_off、逐键力度/压力、可选抢占策略 |
| 音色 | 每次实例锁存0=原参考、1=pluck、2=FM | 正式配置握手、全局能力回报和更多声部资源优化 |
| 包络 | 原声固定基准；动态ADSR构建可锁存A/D/S/R | 通用调参契约、音色专属参数，不能把正弦ADSR直接用于FM/pluck |
| 踏板 | 普通/选择性延音、bank全释放逻辑 | 物理开关、电气、输入去抖；整机panic须同时清理事件队列 |
| 观察 | occupied/gated/sost、分配/拒绝、过载、PCM/clip/deadline | 与system快照接口对齐、序号/CDC、显示域消费者 |

bank的`strike_valid && strike_ready`表示请求被处理；必须看随后`accepted`或`rejected`区分成功与容量/参数拒绝。不能将ready当作“声音已经出来”。16声部原声和8声部多音色是有限池；当前策略保护既有尾音，池满拒绝新实例，没有抢占或自动降低其他声部增益。

这轮还没有给实体琴键定义完整实例令牌。`accepted_slot`只在当前生命周期标识分配位置，释放后会复用；不能拿旧slot号直接释放未来的新音。后续整机接口需同时带实例代次/身份，并测试迟到的松键、同音叠加和声部复用。

多位状态依旧需要一致性快照/CDC后才能给C的显示域使用。左右发送同一PCM，不能由此得到有面积的L/R李萨如图形。现有五份固件只有原时钟/音频加A/B共7个IO；这些逻辑观察信号不能误引成物理顶层端口。

B可直接参考已通过的A/B接法、所需控制功能和模式体验；不要根据本轮五个固件认定最终需要五个旋钮。C可参考状态字段与功能语义，但暂不把这些私有寄存器地址写入蓝牙协议。

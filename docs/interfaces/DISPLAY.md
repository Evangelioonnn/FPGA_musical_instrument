# 显示消费者接口 · 已有信号与待实现适配

现有core能输出voice状态，见[EVENTS](EVENTS.md)。显示按`held`高亮手按、`gated`区分踏板保持、`occupied`区分尾音；一个标志不能混用三种含义。状态顺序和位宽以参数N推导。

| 数据 | expression候选 | baseline当前 |
|---|---|---|
| occupied/held/gated/sost、notes/pitches、envelopes | 已输出 | 已输出 |
| sample/sample_valid/clipped | 混音样本与有效脉冲 | 已输出 |
| gain | 实际平滑增益 | 已输出 |
| weight2/weight3 | 音色混合权重 | 固定0 |
| meter_valid/peak/sample/clip | 每1024有效样本窗口输出，约46.95Hz | 全部固定0，不能用于真实显示 |
| 整机快照、异步FIFO、波形窗口 | 未实现 | 未实现 |

建议首版由A/C协作增加状态快照适配；这里只给设计要求，不假装已有相应模块：

- 每次快照具有一致的声部集合/参数和序号；显示在帧边界采纳新快照，复位/跨域有明确行为。
- 一位事件若可能错过应采用握手/计数，不仅同步脉冲；多位数据用握手稳定窗口或异步FIFO。
- 波形明确取自混音前/后哪个节点、符号位宽、抽取倍数/策略和采样率。读慢时允许丢显示数据且有计数，不能停合成。
- 画幅/缩放与clip标志分离；样本近零不能自动判为“无人演奏”。
- 真实L/R目前同值；两个不同声部、延迟样本或立体声扩展才有不同的二维轨迹含义，屏幕需标注来源。

C可以先写TB生成上述逻辑状态，独立做像素渲染；适配接口冻结后再接A的真实核心。不要在现有耳机顶层为了看信号直接把所有状态引出成GPIO，曾发生859端口超限。

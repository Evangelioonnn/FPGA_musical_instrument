## 接口与数据流

| 模块 | 接手时需要知道的约定 |
|---|---|
| `av_top.v` | 本独立整机连接层；真实V2核心/矩阵/EC11/音频发送＋显示观察端 |
| `av_navigation.v` | USER2短按生成音色脉冲；长按一次翻页，松手不额外换音色 |
| `av_page_writer.v` | 50MHz域接收完整2368位快照、256位扩展和16位键图，转换显示记录 |
| `av_pcm_window.v` | 原始16位L/R连续512样本采集；L上升过零触发，2048样本无过零强制开始 |
| `av_wave_capture.v` | 原始512对先入RAM，求本窗共同峰值，选择共同二次幂显示增益，再发布 |
| `av_frame_ram.v` | 非活动银行写入，请求/确认握手，150MHz域帧边界切银行 |
| `av_renderer.v` | 演奏主屏8级像素流水；中文/数字/25键外形与真实状态 |
| `av_wave_renderer.v` | 波形5级流水、连接采样点、原始峰值/倍率/新鲜度显示 |
| `av_display.v` | 主屏与波形延迟对齐；选页在帧边界更新，总输入输出延迟9像素时钟 |
| `av_timing.v` / `av_dvi_tx.v` | 1080p扫描、TMDS与串行输出、启动复位顺序 |

真实PCM来源为核心 `final_valid/final_left/final_right`（50MHz、每声道signed16），在显示适配层直接观察，与DAC输入相同。观察端ready仅影响采样窗口收集，不回传至发声核心。PLL失锁复位显示观察域，不复位音频。

波形银行为512×40位双缓冲。每字位域：`[39:36]=A`格式标志；`[35:32]`为增益指数n；`[31:24]`为缩放R高8位；`[23:16]`为原始峰值高8位；`[15:8]`为缩放L高8位；`[7:0]`为峰值低8位。所有字重复本窗元数据，保证峰值/倍率与波形原子提交。原始幅值比较请看PEAK，AUTO缩放后的图形高度不能用来比较主音量。

状态和PCM在50MHz域打包；跨域只同步银行请求/确认等单比特控制，宽数据保存在稳定RAM银行。页面切换、显示停顿均不能阻塞音频。采样窗口之间可以有等待触发/帧ACK/复制的缺口；未来FFT必须另接完整PCM及缺口信息，不能用本显示高8位数据当全精度连续音频。左右干声相同，未来李萨如显示直线可能是正确信号结果。

## 板卡与操作

Tang Mega 60K＋NEO Dock，GW5AT-60B，50MHz V22。视频1920×1080、总2200×1125、150MHz像素/750MHz串行、约60.606Hz。非触控；无EDID/DDC、HDCP、HDMI音频。音频保留PT8211右对齐/LSBJ格式。

USER2在Y12，此工程用作音色/换页键，不是彩条工程rstn。USER0 AA13、USER1 AB13为1.5V；EC11 A=T18/B=R17为3.3V，按压未连接。矩阵与音频/TMDS全部针位、Bank电压见DOWNLOAD_ZH.md，合并时必须沿用已核对电气，不混入另一套显示针位。26 IO；J16状态灯未输出。

## 验证结论与边界

六项RTL覆盖状态一致性、16/25键显示适配、换页短长按隔离、连续PCM与触发、静音、同窗峰值、-32768极值、左右比例、双缓冲所有权、实际小信号到像素、完整1080p扫描与TMDS流水。当前主屏仿真像素与此前验收主屏逐字节一致。实际综合/PnR资源和时序只引用 `validation/routed_build.json`，不把独立模块相加。PR1014系统时钟通用路由警告仍需知悉，余量较小。

远端10月10日预算仍给C预留13k Logic/10k Reg/26 BSRAM/16 DSP/1PLL，但Looper真实ADC＋LU1/PCM/命令审计尚有50/150MHz时序失败，CLS与时钟资源也有压力。这里的V2＋显示成功不能代替Looper＋显示成功。A接入时优先使用新平台默认23字LU1，不额外强制保留全LR1声部传输；完整琴键/音色显示需要的字段由双方明确适配。当前PRIMARY/LW各8/8，新接口和效果必须联合布局布线核对。

用户先反馈“能发声、小方块绿色但波形直线”，修复为同窗自动幅度后，本轮确认“波形已经确定可以实施”。将此记为功能性反馈；没有新增板测照片/视频，不冒称25键实体、长时间运行、满载复音、模拟SNR或≤5ms端到端延迟验收。移除未使用旧模块后的干净工程有单独重建记录；若其固件哈希不同，需要补一次SRAM回归。

## 下一位队友如何接手

1. 完整克隆仓库，切本PR分支，先运行 `python tools/verify_delivery.py`；不要把旧UI或本机fallback当依赖。
2. 依DOWNLOAD_ZH.md打开唯一工程，核对器件/顶层、构建、检查实际时序和固件SHA，再用SRAM下载。
3. 按BOARD_TEST_ZH.md记录操作、照片/视频、固件SHA；测到的新问题连同PEAK、倍率、音色、音量、是否发声一起反馈。
4. A接入新Looper/当前平台时，先提供稳定状态/PCM/控制接口及字段单位、版本和复位约定。此交付仍是V2实时演奏，不包含Looper录放状态。不要用旧2368位快照直接猜解新版本。
5. B提供25键实际扫描方式、针位/电平、key_id到MIDI映射，以及可用于UI的独立按钮事件。不要占用演奏键悄悄改变原控制行为。
6. C后续依次增加冻结/时间窗、FFT、真实声道李萨如，再扩展曲库和蓝牙；每阶段先冻结接口和资源增量，重新做整机PnR与板测。

音频回退使用仓库已有 `project/audio_core_v2/audio_v2.gprj`（`audio_v2_top`、19IO），按它自己的约束和构建说明重新生成SRAM固件；本次不上传旧显示/旧波形或任何.fs文件。不要将本独立CST覆盖音频工程，也不写Flash。

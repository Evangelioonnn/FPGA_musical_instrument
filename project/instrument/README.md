# 电子乐器工程：M1 单声部试听

当前版本已经通过 RTL 仿真、综合、布局布线和内部时序检查，并完成首次板卡试听：用户确认左右均衡、主观音准正常、尾音自然，但有随音符出现并变化音高的尖锐附加声，以及静音时仍存在的轻微底噪。音质问题未关闭，不能标记为完整验收。独立 A/B 排查见 `../audio_quality/README.md`。

它是比赛工程的第一块：自动控制事件 → DDS 正弦波 → ADSR → PT8211 → 耳机。当前没有复音和外部按键。

## 现在怎样验证

1. Gowin Designer 可直接打开 `instrument.gprj`，不需要重新建立空工程。器件是 GW5AT-LV60PG484AC1/I0，Version B。
2. 沿用上次成功的供电、DEBUG-USB2 和 3.5 mm 耳机连接。若需插拔耳机，先断电完成连接。初次试听先将耳机放在耳边外侧确认音量。
3. 打开 Gowin Programmer，保持 `GW5AT-60B`，操作选择 **SRAM Program**，文件改为本工程 `impl/pnr/instrument.fs`，执行下载。当前不需要连接矩阵、编码器、FSR 或 LED。
4. 等约 1 秒后，听四个依次升高的音：**C4 → E4 → G4 → C5（do、mi、sol、高音 do）**，每轮约 6 秒。

| 一轮内的时间 | 预期现象 |
|---|---|
| 0～1 秒 | 静音 |
| 1～2 秒 | C4，约 261.63 Hz |
| 2～3 秒 | E4，约 329.63 Hz |
| 3～4 秒 | G4，约 392.00 Hz |
| 4～5 秒 | C5，约 523.25 Hz |
| 5～6 秒 | 静音，然后回到第一个静音槽 |

每个发声槽开始后，约 20 ms 起音、114 ms 降到较弱的保持音量；约 650 ms 模拟松键，随后约 227 ms 尾音衰减到静音。同一音符保持固定音高，没有滑音。正弦波会比上次方波圆润，保持段的音量也更小；数字峰值仍限制在 -512..511，不能据此推断耳机声压。

反馈只需记录：四音顺序是否正确、每音是否有尾音、静音间隔是否干净、双声道是否均衡、是否有明显爆音/意外断音。正常的音符间隔不是断音故障。至少听三个循环。

## 工程阅读顺序

- `src/instrument_top.v`：顶层连接和上电复位。
- `src/demo_events.v`：只生成按下/松开和音符编号；到货后真实键盘从这一接口接入。
- `src/note_table.v`：音符编号转频率控制字，含 128 个 MIDI 音符。实际自动程序仅使用四个。
- `src/synth_voice.v`：32 位相位累加、正弦查表、包络乘法和低音量输出。
- `src/adsr_envelope.v`：起音、衰减、保持、释放；重触发保留当前幅度。
- `src/pt8211_tx.v`：从 audio_probe 提取的输出模块，保持 LSBJ 格式。
- `SPEC.md`：信号与时序契约；`VALIDATION.md`：检查结果与剩余验收。

频率控制字决定音高；每个采样点仍要计算波形幅度。正弦 ROM 保存数学波形的一个周期，不是录音。自动事件序列也不包含音频数据。

## 复现

在你克隆的仓库根目录运行（ModelSim路径可用脚本参数覆盖）：

```powershell
& ./project/instrument/sim/run.ps1
& 'E:/Gowin/Gowin_V1.9.12.03_x64/IDE/bin/gw_sh.exe' project/instrument/build.tcl
```

仿真脚本默认使用现有 ModelSim 10.1d，允许用 `-ModelSimBin` 指定其他安装路径；Python 分析仅需标准库。构建可以在 Gowin Designer 中完成。数学表已提交到工程，不需要每次生成；更改采样率后需运行 `python project/instrument/tools/generate_tables.py` 并同步修改生成公式及相关规格。

`sim/demo_simulated.wav` 是仿真参考声音，并非板卡录音；为了标准 WAV 头使用整数采样率 48077 Hz，验证计算使用精确的 50 MHz/1040。最终仍以耳机上板试听为准。

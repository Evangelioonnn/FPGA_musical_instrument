# 给 C 的接入说明 · Looper session V2

本次开发同步包含接口源码、解包／mock示例、契约和验证摘要；**没有接入你的实际显示工程**。本轮可以先把以下模块加入你的独立集成分支，不替换原V2/SYSTEM_V0接口定义。工程所需源文件及SHA见 `results/SOURCE_MANIFEST.json`；新lab引用的已有兄弟目录也要保留，不能只拷本lab的几个RTL。

## 接法

1. 真实音频链选择 `rtl/session_link.v`，参数默认 AUDIO_N=32 / PLUCK_N=12 / WITH_FULL_STATE=0。它包含原音频、Looper、真实MCP3208 SPI读入、推子pickup、命令和两条观测桥。`sys_clk` 50MHz，采样每1040时钟；`observer_clk`由C提供。模块没有生成像素PLL或指定显示/ADC针位。
2. C按观察域连接 `client_valid/ready`、addr8、value32、tag16；回复 `reply_valid/ready`、原tag、addr8、value32、accepted/applied及reason8。valid受阻时保持整组数据；一个事务在途。**地址0x14..0x17仍是四谐波原始值，0x20..0x2f才是新增UI动作**，勿将十进制20和十六进制20混用。
3. `ui_*` 23字LU1流接 `session_ui_unpacker`，仅 `updated` 时接受其640bit输出；随后可以用 `examples/session_ui_view`解码命名字段。字段属于observer域；显示渲染在VBlank再锁存一次整套状态，避免半帧更新。不要用原LR1解包器读LU1。
4. `pcm_*`是最终混音/主音量后的真实16bit左右样本、32bit序号、gap和session；按valid&&ready取样。画面停顿不得堵塞音频；波形/FFT缓存按序号检查缺口，统计gap而非当成连续采样。
5. `arst`高有效、两域共同复位，域内同步释放。C自身解包器使用observer域同步复位；重新session时清除旧序号/动画/未确认命令。像素域必须持续有时钟。不支持独立复位某一桥域后保留原事务。

`ui_drops/state_drops/pcm_drops/adc_skipped`原始计数以及`pcm_overflow/protocol_error`诊断输出属于sys域，**不能在像素域逐位同步这些多位计数后直接当真实状态**。LU1 word2已安全携带快照drop计数，PCM gap/session为observer域。需要原始计数时另加整组握手快照；单个锁存错误标志可做两级同步。默认详细state输出关闭、为0。LR1详细声部信息仅在WITH_FULL_STATE=1存在，会增加资源，须另跑联合PnR。

## 先做到的画面和交互

- 演奏页：真实菜单音色、主音量目标/应用值、延音/表达状态；物理键亮起。`keys`当前16bit，Loop回放旋律的逐音状态需另开LR1，不能把物理键当全部发声键。鼓动画可用accepted-strike计数差分与last_pad；一帧间多次同时敲击无法完整重建逐击历史。
- Looper页：4轨×4层的实际占用图、当前选轨、锁存录音轨、预备/待边界/录音/播放/停止、循环位置、拍位、小节长度、量化和当前take事件数。错误与clip显示独立提示，不能以“有声音”推断录制已经提交。
- 混音页：4轨实际平滑电平、mute、推子pickup状态，主音量独立常驻；改变轨量不影响其他轨与现场。目标可从成功ACK保存，应用值以新快照为准。
- 全局点击：开关、请求/应用BPM、拍号和拍位，Looper停止时也可以运行。BPM40..240，下一拍更新；40 BPM时切速可能等待约1.5秒。

页面布局和UI选择由C设计。最小版本优先把上述真实状态显示清楚，再加波形/频谱/李萨如和动画。原始左右内容通常相同，L/R李萨如会退化直线；不要伪造独立立体声信号。

## 直接操作例子

所有地址以下均十六进制，value为32bit：

| 操作 | 命令 |
|---|---|
| 从Looper回演奏界面，保留循环 | 20→0；仅切页，**不会停止** |
| 停止循环 | 24→1，幂等，取消未完成take，允许自然尾音 |
| 选轨2 | 22→2 |
| 第一层/下一轮叠录 | 25→1，录音目标轨在请求时锁存 |
| 撤销轨2最后一层 | 26→2 |
| 清轨2 | 27→0x434c5202，UI先提供明确确认 |
| 轨2相对音量50% | 28→0x00048000（2<<17 OR32768） |
| 轨2静音/取消 | 29→5 / 29→4 |
| BPM150、打开点击 | 2a→150，2e→1 |
| 切鼓组/自定义 | 00→6 / 00→5 |

成功ACK只说明请求/目标已提交，不是录音已经开始、清轨已经结束或fade已完成。录制/预备/编辑/flush忙时undo/clear会拒绝；满4层、空轨撤销、参数锁定及错误值都有原因码，不静默截断。

C应做到：等待ACK再开放下一事务；拒绝时显示原因；清轨/撤销等不能因为本地超时自动重复发送；复位后用新快照重建界面。进入自定义页仅切UI页，要编辑音色5时另外发送00→5。不依赖原板盲按长短键或推测目前在哪个模式。

## 独立验证与整合

**物理时序尚有待办：** 保留全部接口、外部150MHz观察时钟的最新审计已完成布线，但有41个setup违例，最差余量−0.368ns；它不是合格的整机候选。19针独立试听工程的50MHz时序已通过，两者范围不同。联合显示时需检查观察域PCM序号/gap计算及音频域参数、事件ready路径，再做整机PnR；接口仿真通过不能代替此步骤。原始报告与各阶段结果见[VALIDATION](VALIDATION.md)。

尚未连音频时，用 `examples/session_ui_mock`→`session_ui_unpacker`→`session_ui_view`测试屏幕；mock只演示合法数据流，不能作为真实状态/录制证据。运行 `tools/check_ui_examples.py`可核对字段与帧格式。

真实接入先验证命令ACK、键/音色/主音量、选轨与记录、undo/clear、轨量，再测阻塞、reset、gap及画面换帧。实际控制板须另做6×6矩阵、25键、3编码器、LED以及J13/Bank电气适配；当前19针下载版仍是4×4替身。预算保留C既定13k Logic/10k Reg/26 BSRAM/16 DSP/1PLL；独立板结果不能代表联合屏幕可放下。最终顶层/约束/PLL与真实C源合并后重新综合、PnR和板测。

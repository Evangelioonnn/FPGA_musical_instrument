## 32声部的明确后续任务

原始无事件寄存版本setup −5.188ns；加一级事件寄存后 −5.458ns，仍是manager的匹配/选择/年龄更新长路径，优化没有达成目标。前后报告都保留在[夜间证据](../../evidence/system_v0_2026-09-19/README.md)。

下一步把候选搜索和状态提交分成时钟阶段，或用顺序扫描分配器替代N×N比较，并提供ready背压。32次搜索在50MHz约0.64μs，远小于人机去抖时间，但要计算同时32事件最坏等待和音频采样截止时间。必须重测同音重触发、抢占优先级、年龄回绕、持续踏板变化、retune提交时点和panic中断；不要用没有协议依据的multicycle/false_path掩盖真实违规。

所有资源表是对应独立顶层的实测结果，不能相加后冒充最终整机PnR。显示、输入和通信消费者接入后将保留更多逻辑，还需时钟、BSRAM与DSP预算。

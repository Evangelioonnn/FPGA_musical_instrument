# 拨弦单声部定点实验

本目录实现用户已认可离线拨弦候选的硬件算法，属于A的独立音色实验；不是既有默认音色的替换，也未接入system的多声部音色选择。目标板为Tang Mega 60K＋NEO Dock。本模块只生成数字样本，不接管引脚或DAC。

后续板测更新：用户确认主体声音与WAV相符，附加变调杂音很轻、接近可接受，但仍存在；见[板测反馈](../../../../evidence/timbre_rtl_2026-09-19/BOARD_LISTENING.md)。没有据此认定音质问题已修复。

9月20日集成补充：`pluck_voice`新增可选参数`LOGIC_SCALE=1`，将乘7864写成等价移位加减以节省DSP。默认0保持本单声部工程的实现选择。优化的精确对照与八声部集成结果见[旋钮候选](../../../input/knob_suite/README.md)；旧报告仍对应9月19日的源码/构建，不重新解释成新构建证据。

## 算法与数值边界

沿用`render_candidates.py`的分数延迟Karplus–Strong模型：噪声激励→线性插值延迟→两点平均低通→约0.997反馈。延迟为`Fs/f - 0.5`，扣除低通的半样本群延迟；Fs精确为50MHz/1040。数学表覆盖MIDI 36～84（C2～C6），不包含任何乐器录音PCM。

1024×24位环形状态使用Q22、一个同步读口和一个同步写口，禁止对RAM整体复位。激励使用xorshift32（13/17/5），取高23位有符号数，再减去整个初始环的均值。seed=0映射为1，避免零状态锁死。原NumPy随机发生器被确定性硬件随机发生器替代，保留噪声激励的模型含义，不能要求与旧离线WAV逐点相等。

分数延迟Q16，均值倒数Q24，反馈常数32670/32768=0.99700927734375；噪声与声部状态为24位，均值累计34位。反馈截断向零，避免负向舍入产生永久DC。原始输出固定系数7864/2²²，再乘velocity/256与释放增益。无逐音归一化。内部插值/均值有24位饱和，最终16位饱和；凸插值、低于1的反馈和限幅力度使原始输出理论绝对值不超过15728。测试观测峰值7573，试听峰值7045，均未触及饱和。

## 接口与时序

端口完全沿用[共享约定](../RTL_SPEC.md)。`cmd_valid && cmd_ready`才接受事务。kind0=on、1=off、2=panic、3=拒绝；非法note_on与保留kind脉冲`cmd_rejected`，不改变当前声音。velocity>256钳位，velocity=0按off，仍要求note合法。off不匹配身份，身份管理由未来多声部管理器承担。

- 时钟50MHz，同步高有效复位；每1040周期给一次`sample_ce`。流水占12周期，可压缩到至少14周期/样本作数值仿真，实际板级输出仍用1040。
- 正常样本在`sample_ce`后12周期出现`sample_valid`；空闲/初始化采样当周期返回0。每个采样脉冲有且仅有一个结果。
- 初始化消耗`4×length+2`周期。最长C2长度736，2946周期=58.92µs；最短C6长度47，190周期=3.8µs。初始化中active=1但采样为0，最多约80µs后出现首个有效数字样本（含等待下一采样）。这不是整机输入至模拟输出延迟证明。
- 初始化中可接受on重触发、off取消、panic取消；正常流水运算期间对普通命令反压，生产者必须保持负载。panic在任何时刻可接受，并将sample立即清零，取消的在途采样返回一次0结果。
- off开始约150ms线性释放，7212采样后active=0且输出精确归零。重复off和velocity0的on不重置正在进行的释放。off与sample_ce同周期时照常生成该帧样本，不插入静音尖点。on与sample_ce同周期时进入初始化，该采样返回0；panic同周期返回0。
- note_on重置延迟状态并重新激励；不做跨音滑音、保留旧弦尾或无点击重触发。持续按住时由模型自然衰减，active保留到off/panic。

## 可复现验证

在仓库根目录运行：

```powershell
& ./project/experiments/timbre/pluck/sim/run.ps1 -ModelSimBin 'E:/QuartusII/modelsim_ase/win32aloem' -PythonExe 'python'
```

Python需NumPy。脚本重新生成数学表，编译`src/pluck_note_table.v`和`src/pluck_voice.v`，运行独立ModelSim库，再分析真实RTL导出的样本。无需readmemh或外部ROM文件。脚本输出在sim目录，不提交ModelSim工作库或大文本样本。

`pluck_tb.v`覆盖非法命令、未知RAM不泄漏、初始化中取消/重触发、运行中panic、复位、相同seed重触发一致、seed0替代、力度钳位、重复off、同周期命令/采样、释放归零，并逐事务检查每个采样只返回一次。`analyze.py`直接用浮点原始0.997算法、理想分数延迟及相同初始激励作为独立期望；不复制RTL移位和流水，也不读取生成的延迟表。

第一轮完整数值验收：

| MIDI音号 | 请求Hz | 仿真测得音分误差 | 浮点对比最大LSB误差 | 相对RMS误差 |
|---|---:|---:|---:|---:|
| 36 | 65.406391 | -0.000025 | 2.245 | 0.0852% |
| 60 | 261.625565 | +0.000399 | 1.921 | 0.1984% |
| 84 | 1046.502261 | -0.001917 | 1.608 | 0.2810% |

音准验收上限5音分；浮点对比上限5LSB且相对RMS<1%。三音均检查自然衰减，力度1/4、1/2、全量的线性与过量钳位均通过。释放长度150.0096ms，释放浮点最大误差1.796LSB，末尾精确静音。该精度是数字模型测量，不表示板卡真实晶振/模拟输出达到同样音准或信噪比。

`sim/pluck_rtl_raw.wav`是直接采集的16位RTL样本，360580样本约7.5秒，未经归一化。10个槽位各约0.75秒，前6音C3/G3/C4/E4/G4/C5，随后C4中力度、弱/中/强三次。第7槽用单个C4代替离线候选中的三音和弦，明确保持本轮单声部范围。已认可的旧离线候选WAV不覆盖。

根任务已提供独立五IO板级probe、Gowin资源/时序和实际1040周期串行检查，并归档数字证据。用户后续给出了上述耳机试听反馈；既有随音高变化的尖锐杂音仍未定位，未完成仪器验收。

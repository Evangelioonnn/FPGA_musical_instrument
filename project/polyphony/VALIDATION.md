# M2 四复音验证记录

日期：2026-09-18。结论：**RTL 功能、样本分析、Gowin 综合/PnR 和内部时序通过；板卡/真实输入验收待做。**

用户反馈（2026-09-18）：听取本工程电脑参考音频后表示“效果还可以”。据此记录参考音频主观试听可接受；没有新增四复音上板证据，原尖锐声仍未解决。

## 验证依据

先定义 `SPEC.md`，再实现管理器和混音模块；复用 M1 声部/串行驱动，不修改已有诊断工程。验证入口为 `sim/run.ps1`。本机使用 ModelSim ALTERA Starter Edition 10.1d 跑纯 Verilog，Python 仅使用标准库。

| 验证 | 结果与范围 |
|---|---|
| `manager_tb` | 6020 个事件向量全部一致；参考模型使用字典和先后顺序列表，独立于 RTL 的等级维护算法 |
| `mixer_tb` | 5008 组向量通过，含 1729 次饱和检查；覆盖 OUTPUT_SHIFT=0/2、正负极值、抵消、负数取整、随机、复位和无效保持 |
| `poly_events_tb` | 四音分配、第五音抢占、旧音松键保护、独立释放、回收复用、同音重触发、全释放、极短按键通过 |
| `poly_render_tb` | 384616 个样本，4 次按下/4 次松开；声部 E3、混音 E4 有效，四路一致，终态释放通过 |
| `poly_transport_tb` | 真实 50 MHz、缩短演示时长，经独立串行接收器检查 3365 帧；四声部占用帧 392、空闲帧 1280、有声帧 2070，左右样本正确 |
| `tools/analyze_poly.py` | 逐样本混音对照、静音归零、多频拟合、独立松键与连续性检查通过，生成 WAV/JSON |

固定随机种子为 20260918；管理器覆盖计数：复位22、回收575、空闲分配647、重触发1303、尾音抢占237、持键抢占791、松键683、忽略1109、全释放93。各计数可能在同一向量中重叠，不是互斥用例数。见 `sim/manager_coverage.json`，测试日志保留在 `sim/*_tb.log`。

八秒音频仿真保留实际包络和音符时长对应的采样数，仅将采样使能间隔压缩为8个系统周期以加速运算；另用 transport 测试检查真实1040周期帧间隔下的串行集成。音频分析按实际 Fs=50MHz/1040 解释样本。

- 混音逐样本等于四个有符号声部样本之和除以4、向负无穷取整；八秒范围为 -306..236，没有溢出。

- WAV为单声道PCM16、48077Hz、384616样本、769276字节；文件整数采样率与实际48076.923Hz存在约1.6ppm差别。未归一化，不是板卡录音。

## 尚未证明的事项

- 未下载本工程，未验收四复音板卡听感、真实频谱或端到端延迟。M1尖锐声仍在，用户计划明天实验室测量。
- 没有Gowin原语仿真/后布局仿真。本次 STA 范围为原SDC约束的内部时序。
- 自动演示可能让工具优化未使用音符分支；资源不能视为完整键盘、力度、音色方案最终占用。
- 四路独立ROM/DSP有明确声部用途；未来增加声部或时分复用需同时比较资源、精度、延迟和时序，不能仅按当前数量线性推算。
- 抢占保持相位/包络但频率会变化，未保证无点击。重复音符只对应一个逻辑持键状态，未支持多输入源同音叠按。
- 每路低幅缩放及混音除4是验证配置；正式精度/模拟增益方案尚待完成。无实际矩阵、力度、踏板、第二种音色。

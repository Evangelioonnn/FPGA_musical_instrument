## 今天先试听

用电脑打开 `sim/polyphony_simulated.wav`，总长约 8 秒：

| 时间 | 应听到的内容 |
|---|---|
| 0–1 秒 | 静音 |
| 1–2 秒 | C4（Do） |
| 2–3 秒 | 加 E4（Mi），两个音同时响 |
| 3–4 秒 | 加 G4（Sol），三个音同时响 |
| 4–5 秒 | 加 C5（高音 Do），四个音同时响 |
| 5–6 秒 | 松开 E4，它的尾音淡出，其余三个音继续 |
| 6–7 秒 | 依次松开其余三个音，尾音收尽 |
| 7–8 秒 | 静音 |

这是 **RTL 仿真样本导出的参考音频，不是板卡录音**。保留了低数字幅度、未归一化，电脑播放可能偏小；可以适当调电脑播放音量。电脑音量设置不影响开发板耳机口。

试听关注声音是否逐层增加、移除一个音后其他音仍持续、最后能否完全收尾。频率、幅值、相位连续性和混音运算已经另用数字分析核对，耳听不替代这些检查。

## 可复用模块

| 模块 | 职责 |
|---|---|
| `voice_manager4` | 按下/松开事件分配给四个声部，处理重触发、尾音回收及第五音抢占 |
| `poly_synth4` | 四套独立 DDS 和 ADSR，接收统一音符事件 |
| `mixer4` | 先扩展位宽相加、固定除以 4，再饱和到 16 位 |
| `poly_demo_events` | 产生上述八秒测试事件，之后可替换为真实输入适配层 |
| `polyphony_top` | 自动事件、核心与原 PT8211 输出连接 |

详细接口以 `SPEC.md` 为准。`event_valid && event_ready` 时接受事件；`event_on` 区分按下/松开，`event_note` 为 MIDI 音符号。所有输入须在 50 MHz 时钟域内同步。核心不承担机械去抖或矩阵鬼键处理。

分配顺序为同音重触发、空闲声部、已松键的最早尾音、全部持键时最早触发的音。被抢占音符之后到来的松键事件不能误关新音。固定混音增益避免松开一个键时其他音突然变响。

在你克隆的仓库根目录的 PowerShell 中运行（ModelSim路径可用脚本参数覆盖）：

```powershell

& 'E:/Gowin/Gowin_V1.9.12.03_x64/IDE/bin/gw_sh.exe' project/polyphony/build.tcl
```

仿真依赖本机 `E:\QuartusII\modelsim_ase\win32aloem` 和 PATH 中的 Python（仅用标准库）。ModelSim 路径可通过 `-ModelSimBin` 指定。脚本检查五项测试的 PASS 标志、错误文本和返回码；音频分析在其后运行。

## 当前边界与后续

- 软件验证详情、资源和时序见 `VALIDATION.md`；文件指纹见 `validation_manifest.json`。
- 本版没有力度、踏板或第二种音色；第五音抢占可能产生瞬态，尚未实现专门的无点击过渡。
- 每路沿用单声部的低幅样本，再混音除以 4。正式音质设计应评估保留更高内部精度、混音后统一缩放，以减少提前量化。
- 四复音数字核心通过不代表普通无二极管 4×4 矩阵能可靠识别任意四键。9 月 20 日到货后先验证扫描、去抖和鬼键限制，再通过音符事件接口接入。
- 板卡音质和完整的输入到声音延迟尚待实测。原问题记录在 `../audio_quality/NOISE_DIAGNOSIS.md`。

# EC11 板级探测工程

这是一个独立的旋转编码器上板验证工程，不是整机顶层，也不修改默认音色基线。

任务角色：A。分支 `feat/ec11-board-probe`，起点 `d96ef7f`；允许目录为本工程和相关状态/板卡记录。目标是把用户实接的 A=T18、B=R17 接入已有解码器和原音色。数字解码/实际DDS变调/串行输出仿真、50MHz构建、实物旋转三层均已完成；上一任务未提交的音质资料保持原状。

## 本次实物接线

| EC11 模块 | NEO Dock / FPGA | 说明 |
|---|---|---|
| VCC | PMOD 3V3 | 首轮使用 3.3 V，禁止接 5 V |
| GND（上方两针中的 GND） | PMOD GND | 模块供电地 |
| C（A/C/B 中间针） | 不连接 | 客服建议悬空；实测C–VCC约9.9kΩ、C–GND开路，不是直接接地公共端 |
| A | FPGA 球号 T18 | 本工程约束为输入、内部上拉 |
| B | FPGA 球号 R17 | 本工程约束为输入、内部上拉 |

使用前拔下 PMOD-LEDx8，避免同一信号同时连接 LED 和编码器。FPGA 球号不是排针的物理针序；接线按板上 PMOD 的 3V3/GND 丝印和已核对的信号行确认。

模块图片把 C 标为公共端（GND），但用户随后反馈客服图示让 C 悬空。VCC 对 GND 实测 3.3V；VCC 对 C 没读数不是导通证据。用户重新用电阻档测得 **C–VCC约9.9kΩ、C–GND一直超量程，按压不改变**。据此C不是直接接地公共端，可能通过电阻上拉到VCC；不能凭此进一步认定是按键输出。最初“都是0”的读数已被本次更明确读数取代。**撤回此前“必须把 C 接地”的指引，保持C悬空，只使用VCC/GND/A/B四根线。** 未确认独立按压输出，本轮不绑定按压功能。

用户已确认本模块在上述3.3V四线接法下旋转正常。商品标称5V不构成FPGA可承受5V输入的依据；继续使用3.3V。后续排查电阻/通断时须先拔掉模块所有连线；本轮未测A/B电压波形或长期可靠性。

## 预期现象

插好耳机后下载 SRAM，工程从 A4（440Hz）开始，使用原正弦DDS和ADSR 68/6/32768/3，按住不释放。每个完整正交周期（4次合法相位转移）改变一个半音；顺、逆方向分别改变音高。静止时保持最后音高，音符范围C3–C6（48–84），到边界停住、不回绕。由于持续按住，初次起音之后听到的是保持段，不会每转一格重新弹奏一次。按压输入 `button_n` 固定为高电平。

实物板测确认本模块每个机械卡点触发一次音高变化，当前 `EC11_STEPS_PER_DETENT=4` 正好匹配。初次方向以实物记录为准，未承诺顺时针一定升高；整机若要反向只交换A/B语义。

方向若与预期相反，记录结果，后续交换软件输入即可；物理换线必须先断开板卡全部电源。

## 验证边界

- `ec11_input.v` 的同步、去抖和4相位解码在当前实物试听中实现每格一次；尚未用示波器记录A/B相位波形。
- RTL仿真、综合/PnR和用户耳机板测均已完成；这只证明本探针的EC11→DDS→PT8211路径，不能替代最终整机多键、复音、端到端延迟和长期可靠性验收。
- 此工程的约束只占用 `T18`、`R17`、现有音频四线和 `V22` 时钟；不得作为最终整机 CST 直接合并。
